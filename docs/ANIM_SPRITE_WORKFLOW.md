# 单位分帧动画生成工作流（agnes-video-2.5-flash）

> 2026-08-29 首次跑通并定型。3 单位（虎式坦克/暴风突击队/阿帕奇）× idle/attack 共 6 套成品。
> 本文档 = 完整操作手册 + 踩坑记录。工具：`tools/generate_unit_animations.py`。
> 与 `docs/ART_PIPELINE_AI_ICON_GENERATION.md`（静态卡图）互补，本篇是动态分帧动画管线。

## 〇、协作流程铁律（2026-08-29 定稿，用户拍板）

每个敌方卡单位按此流水线走，**任何人改流程须先经用户确认**：

```
① 生成视频（卡图→白底ref→imgbb→keyframe任务）
② AI 自检关卡：朝向向左/转头掉头/开火方向/白底纯净/动作幅度
     ├─ 有问题 → 直接重新生成视频，不往下走
     └─ 没问题 → 进入③
③ 出分帧图存 资料/单位分帧动画/<单位>/<动画>/f*.png
     ⚠️ 分帧图是唯一可编辑真身，一律保留不删
④ 在分帧图之上做精灵图动画（sheet + preview）
⑤ 用户人工审查关卡：preview 逐套看，标出问题帧
⑥ 修改：用户自己改个别帧，或 AI 统一批量改分帧图（删帧/镜像/重抠图）
⑦ 重建精灵动画 → 用户确认 → 该套定稿
```

**核心原则：分帧图 = 可编辑源；雪碧图/精灵动画 = 派生物，改完帧随时重建。任何阶段不删分帧图。**

## 一、产出规范

```
资料/单位分帧动画/
  <unit_id>_<中文名>/
    idle/    f00~fNN.png (512×512 RGBA透明) + sheet_idle.png(横向雪碧图)
             + meta.json + source.mp4 + raw/(ffmpeg原始抽帧,可重处理)
    attack/  同上
  preview.html          全部动画循环预览页(CSS steps播放)
  _ref/                 白底化参考图(imgbb上传源)
```

- **帧数**：idle 8 帧（抽稀后可 7）、attack 12 帧（删坏帧后可 10）
- **建议 fps**：idle 8 / attack 10（meta.json 有记录）
- **画布**：512×512 透明；地面单位脚底对齐 92% 高度线，空中单位 80%
- **朝向铁律：敌方卡全部朝左**（与 `vis_enemy_*` 原图一致；我方 = 引擎侧水平翻转）
- 每帧相对位置由**全帧并集 bbox** 统一画幅锁定（防抖动）

## 二、生成链路

```
敌方卡图 vis_enemy_NNN.png (512²透明)
  → PIL 白底化 → _ref/<unit>_white.jpg
  → imgbb 托管 (https://api.imgbb.com/1/upload, key 见 tools 脚本, expiration=3600)
  → POST /v1/videos  {model:"agnes-video-2.5-flash", mode:"keyframe",
      first_frame:<imgbb URL>, seconds:"4"~"5", size:"720P", aspect_ratio:"16:9"}
  → 轮询 GET /agnesapi?video_id=<id>&model_name=agnes-video-2.5-flash (每4s)
  → completed 后下载 mp4 (80~150s/段)
  → ffmpeg -vf fps=8 抽帧 (4s→36帧, 5s→41帧)
  → 抠图 v6(见四) + 亮度校平 + 并集bbox + 512画布 + 雪碧图 + meta.json
```

## 三、Prompt 模板铁律（血泪教训）

每条 prompt 必须包含（完整模板见脚本 UNITS 定义）：

1. **外观锚定**："严格保持首帧图像中…的外观、比例、涂装与细节完全一致，不改变设计"
2. **朝向锁死**："始终保持首帧的朝向，[炮管/枪口/机头]指向画面**左侧**，绝不掉头，绝不转向"
   - ⚠️ 教训1：早期写"向画面右侧方向开火"→ 攻击动画全部反向生成
   - ⚠️ 教训2：人形单位头部要单独加码："头部如雕像般固定，不转头，不回眸，不低头，不看向镜头"——否则模型会把"张望"演出转头甚至转体
3. **视角铁律**："严格2D游戏精灵风格，平面正交正侧视"（复用卡图 STRICT_PREFIX 体系）
4. **锁镜头**："镜头完全锁定，无运镜，无变焦，无平移，单位始终完整在画面内不被裁切"
5. **白底**："纯白色无缝背景，无地面，无阴影，无文字，无水印"
6. **idle 专用**（无缝循环）："动作结尾精确回到起始姿态，首尾帧一致，动作平滑无缝循环"
   - 不写这句 → 炮管/姿态结尾不回位 → 循环接缝跳变（实测接缝差 32.9 → 加此句 11.5）
7. **attack 专用**：单次动作描述（开炮一次/连射），方向向左，弹壳"向右后方抛出"

### 生成质量随机性

同 prompt 每次 roll 结果不同（种子随机）。实测问题率：头部转动 ~50%（人形）、朝向翻转偶发。
**对策**：删帧/镜像等后处理优先于重生成；重生成免费但又是抽卡。

## 四、抠图算法 v6：主体连通域法（最终版）

**核心认知：主体（深色/高饱和）与垃圾（浅色低饱和）天然可分，不要试图枚举背景形态。**

垃圾清单（全部实测遇到过）：纯白底 / 压缩斑块状近白 / **视频模型自画的内嵌暖灰矩形框线**（距边约40px，sat 55~70）/ 枪口烟云（实心灰团）/ 脚下灰影渐变。

```
ok = (min通道 >= 135) 且 (饱和度 <= 75)        # 垃圾特征域
泛洪种子 = 图边界8点 + 中部行列扫描的纯白长run中点   # 双路, 框线隔开的两片白都要种
floodfill over ok 连通域 → killed
keep候选 = ~killed → 连通域标记 → 只留最大连通块   # = 单位本体, 框线环/烟岛出局
脚线清扫(实体最深行+4px以下) → 高斯羽化0.8 → alpha
```

### Pillow 踩坑记录（脚本注释里也有，勿重蹈）

| 坑 | 现象 | 规避 |
|----|------|------|
| `Image.fromarray` 缓冲别名 | floodfill 写入后 getpixel/asarray 读到旧数据，抠图静默失效 | 掩码用 `Image.new + putdata` 构造，读结果走 `tobytes()` |
| floodfill `thresh=0` | 相邻等值像素也不扩散，每次只填种子点 | 二值掩码一律 `thresh=1` |
| floodfill thresh 语义 | 与**种子色**比对，非相邻渐变跟随 | 想跟渐变得自写 BFS（最终方案不需要了） |
| 连通域面积累计 | 多组件全填同一值再 count，面积越算越大，best 选错 | 每组件用递增值填充分别 count |

### 后处理链

1. **亮度校平**：逐帧不透明区均值向首帧对齐（gain 钳 0.92~1.10）——治视频光源呼吸（实测 -7% 弧线）
2. **并集 bbox**：全部帧 alpha bbox 的并集统一裁剪 → 帧间零位移
3. **删帧**（实战操作，见下节）后重编号 f00 起
4. **雪碧图**：横向拼接，meta.json 记帧数/建议fps/来源任务id

## 五、实战修正操作手册（本次 6 处）

| 症状 | 处理 | 命令/方法 |
|------|------|----------|
| idle 混入开火帧 | 删该帧+重编号+重拼sheet | `os.remove(f01)` → rename → sheet |
| 头部转动帧（人形） | 删帧（前2帧）再评估是否镜像 | 同上 |
| 整组朝向反了 | 水平镜像全部帧 `ImageOps.mirror` | 注意：**先确认卡图朝向**再决定镜像（本次暴风一次误判，白翻一次） |
| 脚下白/灰残留 | v6 抠图重跑（勿再用阈值补丁） | `python tools/generate_unit_animations.py build <unit> <anim>` |
| 循环接缝跳变 | idle prompt 加"回位"句重生成；或引擎 ping-pong 播放 | — |
| 帧太密/太稀 | 调 `raw_fps`（step_build 参数，默认8） | — |

## 六、QA 指标（`check` 子命令）

```
python tools/generate_unit_animations.py check
```

| 指标 | 方法 | 通过线 |
|------|------|--------|
| 朝向 | 列像素轮廓 vs 参考卡正/镜像相关度（逐帧） | 全帧向左（对称构图卡此指标弱，以人眼为准） |
| 循环接缝 | 末帧vs首帧不透明区 RGB 平均差 | idle < 15 优；attack 单次播放可放宽 |
| 白残留 | 不透明区内 min通道>=240 占比 | < 0.2% |
| 脚下残留 | 内容底部25%行内不透明浅灰占比 | = 0% |

2026-08-29 终版数字：全部朝左；接缝 idle 7.9~14.2 / attack 13.1~26.8；残留 ≤0.16%；脚下 0.00%。
