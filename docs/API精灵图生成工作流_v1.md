# API 精灵图生成工作流（纯 API，v1）

> 2026-10-12 立项。目标：替代/补充现有两条路线中质量不稳的部分，**纯 API 驱动，不走 Flow 浏览器**。
> 方法论来源：公开技能库 spritecook-generate-sprites + game-assets-2d（已安装到 Hermes profile，
> 本地路径 `~/AppData/Local/hermes/skills/spritecook-generate-sprites/`、`.../game-assets-2d/`），
> 结合项目既有沉淀（`tools/_agnes_image_api.md` 行为实测 + FLOW 品红键控 + §12 交验门禁）。
> 与旧路线关系：不混用键控/锚定口径；本工作流产物同样只落暂存目录，过门禁才部署。

## 1. 路线定位

| | agnes t2i（v3 旧流程） | FLOW i2i（现役） | 本工作流 |
|---|---|---|---|
| 驱动方式 | API | 浏览器 | API |
| 一致性来源 | 无（裸 t2i，prompt 每张重写） | 底稿 i2i | **现役资产 i2i + 单变量纪律** |
| 抠图 | 绿底键控 | 品红键控 | 沿用品红/绿底（按资产类型，不新造口径） |

旧流程效果不稳的根因诊断（对照 game-assets-2d 的归因）：整套资产每次生成时 prompt 整段重写，
风格/视角/光照/底色全是变量——模型端没有任何东西被"锁住"。

## 2. 核心质量纪律（本工作流的四根支柱）

1. **参考图锁外观（i2i 而非裸 t2i）**
   - 每个单位选定一张"单一事实来源"参考图：现役 idle f0 或卡图。
   - agnes-image-2.1-flash i2i 已验证可用（先例 `tools/bg_rework/ai_rework.py`）：
     payload 加 `"extra_body": {"image": ["data:image/png;base64,<b64>"], "response_format": "url"}`，
     **生效判据 = 返回 URL 含 `/i2i/`**；不含则实际跑的是 t2i，必须当作失败重试。
2. **单变量纪律（game-assets-2d 最有价值的一条）**
   - 固定：参考图 + prompt 骨架 + 底色 + 尺寸 + 模型，全部冻结。
   - 每张图**只允许换一个槽位**：主体描述句 `{SUBJECT}`。
   - 严禁为单卡"顺手优化"骨架文案——要改骨架，整批重跑。
3. **统一纯色底出图，透明全靠后期**
   - 模型出不了原生 alpha（spritecook 明确结论）。底色按资产类型沿用现役口径
     （帧=品红，卡图=绿底 #00FF00 或白底 flood），prompt 里把底色锁死为
     "solid flat magenta #FF00FF background ONLY"这类正面意象句。
   - 正面意象锁死规则照旧（`tools/_agnes_image_api.md`）：负面列表只留结构性排除
     （text / perspective view / frame），不写概念性负面词。
4. **先静帧后派生（slice first, animate afterward）**
   - 静帧先过质检门，动画帧从过审静帧 i2i 派生，不从零生成。

## 3. Prompt 骨架模板

骨架冻结入库，批次内只替换 `{SUBJECT}`：

```
STRICTLY a pure 2D side profile silhouette view, absolutely NO front view,
NO three-quarter view, flat orthographic game sprite, single subject only centered,
{SUBJECT}
matte painting style, detailed weathering and surface texture,
complex dramatic lighting with rim light from top-left,
solid flat {KEY_COLOR} background ONLY, the background is one perfectly uniform
flat color with no gradients and no lighting falloff,
centered composition, full body fitting in frame with generous empty margin,
NO text, NO watermark, NO ground, NO shadow, NO scene background
```

- `{SUBJECT}` 写法：正面意象锁死——描述"该画什么"（机体/兵种/武器构成），不给"不要什么"。
- `{KEY_COLOR}`：品红 `magenta #FF00FF`（帧）/ `chroma key green #00FF00`（卡图），与后期键控一致。
- 多资产批量（道具/图标类，可选）：借 spritecook 六宫格法——一张图 2×3/3×3 网格、
  逐行列对象、格间大留白、无标签无网格线、统一视角与色板，生成后按网格切开。
  单位主体（需逐张控角度/脚位的）仍走单张 i2i。

## 4. API 调用规格

- 模型 `agnes-image-2.1-flash`，端点 `POST https://apihub.agnes-ai.com/v1/images/generations`，
  key 运行时读 `tools/_api_key.txt` / config.yaml（3 key 轮换，不入 git）。
- `curl --http1.1`（实测稳定姿势）；1024x1024 或 1152x768；单张 30~60s，批间 3s。
- t2i payload：`{"model": ..., "prompt": ..., "image_size": "1024x1024"}`。
- i2i payload：t2i 基础上加 `extra_body.image`（base64 data URI 数组），见 §2.1。
- 批量执行借 comfyui skill 的脚本分层：`health_check`（连通性+单张试掷）→
  `run_batch`（批生成+逐项 JSON 台账：prompt 原文/尺寸/耗时/返回 URL/落盘路径/i2i 标志）→
  失败自动按 key 轮换重试一次。

## 6. 质量门（自动化预检 + 人工终审）

### 6.1 动作语义标准（开火循环 7 条, 2026-10-12 试点沉淀——几何指标全对≠动作成立）

1. 节奏结构：预备(1帧)→瞄准蓄势(1帧)→击发(1帧,唯一带焰)→后坐顶点(1帧)→回位(1帧)→归稳(1帧)
2. 枪口焰只在击发帧出现一次（第二处焰=误读两枪）
3. 枪的运动路径连续（胸→肩→肩后坐→回落→待机, 不许瞬移）
4. 质心连续（重心移动有因果, 不许无故换站/跪姿）
5. 朝向恒定：全程纯侧面朝左, 脸和枪口不转向镜头
6. 循环闭合：末帧姿态能自然接回 idle（实践: f6 用瞄准变体与 f2 呼应即可, 不必精确等于 idle f0）
7. 几何前提：大小一致/落地线一致/无截断——必要不充分

自动审计门（脚本内置）：主连通域恰 6 个、逐排落地线漂移≤40px、f5/f6 宽高比≥0.4（空手坏卷签名）、
全局统一缩放（瞄准帧定标, 禁逐帧 bbox 归一）+ 画布安全钳位。语义 7 条由目检执行。

自动预检（部署前脚本量化，不过不进人工环节）：
- i2i 标志：返回 URL 含 `/i2i/`，否则整张作废；
- alpha 占比 > 30%（低于 = 底色不纯，查原图）；
- 主体 bbox：内容占比、脚部锚位与同族现役帧对齐（沿 §12 口径）；
- 四角采样底色与 {KEY_COLOR} 偏差 < 阈值。

人工终审沿用现有门禁：帧类按 `docs/FLOW_精灵帧生成工作流.md` §12 G0~G12 逐条全过；
卡图按 v3 工作流 8 项清单。风格一致性终审标准（借 game-assets-2d quality bar）：
- 整批读起来是一套（无"异类感"）；
- 应保持的结构（轮廓/比例）与参考图一致，应变化的只有预期细节；
- 边缘无 halo/底色残边，小尺寸下仍可读。

## 7. 试点验证（2026-10-12，ww2_arm_garand_para，已完成）

结果：**6 帧 attack sheet 生成通过目检**，产物在 `.godot/unit_review/api_ww2_arm_garand_para/`
（sheet_attack_api.png + frames/ + compare_api.html + ledger.json），参考实现
`tools/api_sprite_pipeline/generate_attack_api.py`。未部署——仍需 §12 门禁 + 实机验收。

试点沉淀的硬结论（已固化进脚本）：
1. **i2i 输出强制 1024²**，不跟随 image_size 请求也不跟随参考图比例 → 底稿必须原生 1024²。
2. **纯 prompt 描述多面板网格会被无视**（画成单图）→ 必须**程序化拼 6 格底稿**锁布局（FLOW 底稿法的 API 化）。
3. **逐帧单掷模式作废**：帧间武器/盔网/朝向漂移，QC 不通过；网格单次生成帧间天然一致。
4. 逐格硬性不变量（朝左/持枪/铁瞄）必须逐格重复写，否则出现翻面/空手/带镜；枪口焰必须写明"贴住枪口"。
5. 投影 prompt 压不住（"no shadow"反激活）→ 键控层扩键解决：紫红投影判据
   `r>90 & b>0.55r & g<0.5·min(r,b)`（棕靴 b<g、描边 r≤90 安全），外加最大连通域剔除。
6. 掷与掷方差大 → 生成-审计-目检-重掷循环（几何门自动判废, 语义 7 条目检）。
7. `tools/_api_key.txt` 第 2 把 key 已失效（401 Invalid token），轮换机制自动跳过；建议清理。
8. **禁止整格"编辑式"修格**（"只改某格其余保持"）：模型会整图重掷（抹格/全局漂移），坏格只能整卷重掷或单帧重画拼接。
9. pose 文案禁否定句（"no flash/no smoke"反激活成空手待机, 两卷实证）、禁翻面诱导词（"muzzle kicked up"诱发朝右开火）。
10. **禁逐帧 bbox 归一**：竖枪/后坐帧 bbox 含枪械越伸, 归一会把人体缩小 25%+ → 全局统一缩放
    （瞄准帧定标）+ 画布安全钳位；单帧修补用体高行密度法（`splice_frame.py`）。
11. 固定 1/3 切格会切掉枪口越伸 → 整图键控+连通域提取（`grid_to_frames`）。
12. "收势/待机"姿态是模型顽固空手重灾区（五连坏卷），该位置用瞄准变体占位最稳。

已知残留（交人工审，2026-10-12 终版卷）：f1 为单帧修补拼接（splice_frame.py, 体高 227 对齐），
色调与网格帧有轻微色差（偏橄榄棕），后续可整卷重掷消；f5 背囊比其他帧明显；
枪口焰白心边缘疑似特效自有粉色调（放大复核）。

## 7.2 card4 批（2026-10-12 晚，用户实机两点拍板后重做——`--mode card4` 定稿路线）

用户实机两点反馈：①粗描线 idle 底稿→成品发闷失精细，应换 **512 干净卡图**当锚；
②"不必要帧可用其他帧代替"→ 定案 **首尾帧=原卡图书挡，中间只出 4 动作帧**。

**分辨率实测（关键前提）**：`image_size=2048x2048` 请求，i2i **返回仍 1024×1024**（`probe_2048_result.json`，
49s）——此端点出图锁死 1024²，喂更大参考图无效。所以"高像素"这条路走不通，**真正杠杆是
一张图塞更少帧**：4 格（每格 512、人物 ~440px 不上降采样）比 6 格（每格 341、人物 269px）

## 7.3 cardgen 批 + 横向锚定/光影勘误（2026-10-12 深夜，用户实机三连反馈后重做——`--mode cardgen` 定稿路线）

用户实机三连反馈：①原 512 卡图质量不行（残留白底+色差+放进精灵帧方向错），不能当书挡；
②"首尾帧用一张新生成卡图代替原卡图"；③"合成的精灵帧方向总是不对"。逐条处置：

**① 反向 i2i 产新卡图（`--mode cardgen`）**：拿 card4 的 f2(瞄准帧, 干净)做 i2i 参考，
`CARD_READY_POSE`（行军准备姿, 朝左, 枪垂身侧）出一张 512 透明底新卡图（`new_card.png`）——
与动作帧**同风格/同色/同朝向**，根治旧卡图色差/白底/方向错。再用它补 f1/f6 书挡（`render_bookend`）。
定案卷：新卡图 + 4 动作帧 f2~f5，合成 6 帧 `[新卡, f2, f3, f4, f5, 新卡]`。

**② 横向锚定勘误（`stance_x_of`，本批头号缺陷根治）**：旧 `normalize_frame` 把每帧**水平居中**
（`(canvas-cw)//2`），但各帧内容宽差大（开火帧带焰更宽）→ 居中后**人体左右跳**（实测 6 帧脚部 x 从

## 7.5 动作幅度原则 + 反帧自动门（2026-10-12 深夜，"动作太大→跳变大" 拍板）
