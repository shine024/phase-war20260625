## 四、踩坑记录（换机必读）

1. **agnes 假扩展名（本日最大坑）**：下载的".jpeg"实为 **PNG 内容**——浏览器按内容嗅探没事，Godot 按扩展名分发解码器直接炸，且**导入静默不落地**（`.import` 写出 `valid=false`，无报错）。遇导入不落地先 `PIL Image.open().format` 查真实格式。
2. **headless 导入队列**：`--editor --quit` 会中断队列（一轮只落 1-2 张）；批量资产多跑几轮或让 GUI 编辑器自己导。真 PNG 一次全过。
3. **TextureButton 没有 `click_mask`（4.5）**：属性名是 **`texture_click_mask`**；`BitMap.create_from_image_alpha` 是**实例方法**（先 BitMap.new()）。
4. **`--script` 模式无 autoload**：脚本加载会刷 "Identifier not found"（SaveManager/GameManager 等）编译噪音——结构性断言（常量表/源码片段）可用；方法级运行时验证必须带窗口跑场景（SceneTree 探针 + `res://tests/xxx.tscn` 跑法）。
5. **gdtoolkit 4.5.0 误报**：world_map.gd 存量多行字符串（`tooltip_text += "` 换行续写）解析报错，引擎本身接受——world_map.gd 跳过 gdparse，以引擎加载为准。
6. **battle_ended 时关卡号已推进**：胜利链 `set_current_level(max_unlocked)` 先于后连的 handler——开打时从 `SignalBus.battle_started` 抓关号存 `_pending_battle_level`。
7. **BattleInfoDisplay 击杀口径**：`get_battle_stats().player_kills` = 我方击杀（敌方死亡数）；节点在 main.tscn 墓碑（BattleTopStatusBar）内，battle_ended 时仍存活，`tree.root.find_child` 可达。
8. **热区定位法**：PIL 打 50px 网格（红线 200 标尺+坐标标注）→ Read 目读 → 百分比存表；1312×736 与 1376×768 混用时各图百分比独立成表（truck_base.HOTSPOTS 按 era 键）。
9. **LevelProgressManager vs GameManager 口径**：`get_max_unlocked_level()`（星级进度）与 `GameManager.current_level`（所在关）可能不一致——显示/出击一律用后者（与地图标记同源）。

### 7.1 管线：tools/generate_truck_img2img.py

- **API 形态**（官方文档 apihub.agnes-ai.com/docs/agnes-image-21-flash）：请求体加
  `extra_body.image = ["data:image/jpeg;base64,..."]`（Data URI），prompt 只写编辑指令；
  `response_format` 也必须放 extra_body 内。**无 strength 参数**，保留度全靠提示词，
  官方推荐结构 = [改变要求] + [添加/移除元素] + [要保留的元素]。
- **两张母本（都是用户亲手给的图）**：
  - 外观 = `generated_truck_sprite/library_hero_..._2K_202609051213.jpeg`（tier5 悬浮装甲列车）→ T1-T4 降档派生；T5=母本本体不重生成。
  - 剖面 = `单独图/Gravity_well_..._1734.jpeg`（用户最初认可的剖面：电脑桌+地图/贩卖机/3D打印/柜/床）→ cut1-5 升档派生，背景改纯白供抠图。
- **提示词教训（img2img 特有）**：
  1. "downgrade to a present-day conventional military truck" 这类**主体改名**会让模型整辆重画（T1 首轮变成普通 6×6 卡车+照片风）——必须逐条列死母本特征锚定（超长车体 7-8 倍车头/列车式斜鼻/上排小窗/同位换轮）。
  2. "换轮子/降档"类结构改动漂移最大；"加设备"类改动最保真（tier4 加悬浮垫/电轨炮一次过）。
  3. 拆母本高位装备（红激光炮/碟形雷达）必须显式写移除，否则一直保留（T2 二轮才拆掉）。
- **抠图后处理链（deploy）**：`_flood_bg`（颜色感知泛洪：近白+浅中性+浅青辉光都可过，解决 JPEG 光晕桥挡泛洪）→ 封白 → `_kill_ground_band`（底带中性灰：外观 y>0.70h/剖面 y>0.80h，轮胎 mx≈34 不受伤）→ `_remove_detached_ground_blobs`（连通域删脱落光池：tier4/cut4/cut5 青色反重力光池饱和度高、颜色规则删不掉）→ autocrop。
- **残留底色袋**：阴影(中性灰)挡泛洪路径会在轮间兜住浅色背景袋——剖面 y>0.80h 底带 + 驾驶室/厢体夹角定点矩形（`_kill_neutral_rect` 0.23-0.37w/0.62-0.76h，五图同位）。

### 7.4 剖面 v2 派生法（用户再纠："剖面图不是用原图生成的"）

- 问题：v1 五张剖面虽然传了原图，但每张 prompt 同时要求"背景白化+换轮+升档"多重编辑，
  模型每次整辆重画——五张各不相同、驾驶室车体全漂。
- **v2 = 两步派生**：
  1. `cut_base`（仅背景白化，一条编辑指令："Do not redraw the vehicle"，其余像素级保留）
     —— 实测 **.cn 端点比 .com 保真**（.cn 版 3D 打印橙件/单床都在；.com 把打印件换成了
     青圈机器还多画一张床），落 `_i2i/cut_base_cn.jpeg`；
  2. cut1 = cut_base 直接拷贝（原图即现代档，零漂移）；cut2-5 全部从 cut_base **星形派生**
     （每张只加本档设备：焊板/反应装甲+雷达/全息屏+机械臂/相位青光），提示词以
     "Keep ... EXACTLY at the same position ... Do not redraw the vehicle. Only change this: ..." 锁死。
- 结论：**img2img 一次只做一类编辑、编辑量越小越保真**；多重编辑=整辆重画。
  无 strength 参数的 flash 档图生图，把"原图"当强参考而非锁定，保真度全靠把编辑切小。
- 热区：五档共享同一布局 → HOTSPOTS 五档同表（PIL 网格实测 cut1：电脑桌/地图/工作台/
  售货机/打印位/柜/床(厢内右上)/设备架/尾板），smoke + UI 审计 ALL PASS。
- 教训（流程）：gdparse 失败会 `&&` 断链跳过导入循环——部署链里"解析→导入→审计"
  要用 `;` 分段或独立跑，别让一步失败静默跳过导入。
