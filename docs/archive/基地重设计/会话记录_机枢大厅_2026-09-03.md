## 二、现行方案一句话（机枢大厅）

**场景给地方感（机器一间间亮），面板给运营感（工具一代代换），不要 NPC，基地自己是主角。**
- 场景：1280×720 单屏废弃车间，9 台大机器（发电机/沙盘台/实验台/分析仪/电台/充能舱/工作台/炊事机/打印机），三态=残破→运转→外挂件升级；后墙 30 盏纪念铜灯（亮 5 暗 25）+ 封死的终局之门
- 面板：H1 总览（分组列表/状态/"还差N场"/成本/队列/目标链）恒定，**容器皮肤三档进化**：T1 白板（默认）→ T2 显示器（6 台运转）→ T3 投影（9 台运转+发电机 Lv2），换肤=演出高光时刻
- 交互：点机器即开面板（先响应后演出，零寻路）；出击=沙盘台或顶栏按钮，≤2 击进战场
- 功能映射（15 房合并为 9 站）见 `基地方案_机枢大厅.md` §二

## 四、网页原型说明（`machine_hall_mockup.html`）

浏览器直接打开（无需服务器，纯静态+vanilla JS）。**文件引用为相对路径 `generated_mh/`，HTML 必须留在 `docs/基地重设计/` 目录**。
- 顶栏：天数/精神/四资源/基地加成汇总条 + **模拟出击+1场**（推进所有修复/升级进度并触发产出）+ 一键收取 + 晨报
- 左场景：底图 + 9 机器（点击=选中/修复；气泡=收取）；**左下角底图切换器**（原/A/B/C/D）
- 右面板：分组站点列表（状态/耗时/成本/行内修复升级按钮）+ 机器详情（功能按钮+升级路线）+ **皮肤三档切换**（T2/T3 锁定条件真实联动：运转台数+发电机等级）
- 数据模型：JS `S` 表 = 每机器 `rect:[x, 底部基线y, 宽]`（后排基线≈320 踩高台，前排≈596 踩地板，图加载后自动按高度回算 top）——**调布局只改这一处**
- 状态机：locked→repairing（按场推进）→active(Lv1-3)，与 BunkerManager 语义同构

## 六、技术坑沉淀（换环境必读）

1. **agnes 生图行为**（详见 `tools/_agnes_image_api.md` 实测段）：负面词基本无效且反激活，只留结构性排除（text/perspective/frame）；**正面意象锁死**是唯一可靠手段；风格词禁 gritty/somber/dusty（会带垃圾进画面）；屏幕/灯内容必须显式限定"abstract patterns only"；单张 30-60s，3 key 轮换。
2. **抠图必须边缘泛洪**，不能用全局亮度阈值（`deploy_card_icons_11.py` 的做法会把机器上的白灯/白汽/白卡抠掉）——`cutout_machine_hall_sprites.py` 的实现是正确参照。
3. **本会话沙箱三坑**（换环境若再现）：①HTTPS 出站全被阻断需放行；②`subprocess` 管道捕获 EPERM（改 `stdout=DEVNULL`，响应走 `-o` 文件）；③**curl 在中文/空格路径下 ANSI 编码静默失败**——所以生成器用纯 `urllib`（HTTP/1.1 天然满足，无需 curl）。
4. **底图命名约定**：`mh_hall_bg_{a,b,c,d}.jpeg`（生成器 HALL_VARIANTS 键 bg_a-d；曾因 `mh_hall_a` vs `mh_hall_bg_a` 不一致导致网页 404，已修正）。
5. API key 两套独立：生图 key 在 `tools/_agnes_image_api.md`，视频 key 在 `tools/_api_key.txt`，均不入 git/zip。

## 八、2026-09-04 视觉审查轮（浏览器实拍全状态 + 资产近距对照）

**方法**：本地 HTTP 起服 + 浏览器实拍原型全状态（5 底图/皮肤三档/全运转态/晨报），
PIL 拼资产对照图 `.godot_review_machines.png`（9 机器两态）与 `.godot_review_panels_bgs.png`
（3 面板皮肤 + 5 底图）——两图为临时审查件（png 不入 git），可删。

**总体结论：方案成立，资产质量过关。** 机器两态连贯性：充能舱/工作台/炊事机/分析仪/沙盘台
优秀（同 silhouette 翻新感），发电机/实验台/打印机良好（轮廓换代但同族），电台运转态明显
变小（修好反而缩水）——电台 active 可单点重生成。残骸态锈橙是统一的"待修"信号。

**本轮已修（原型 3 缺陷，已回归截图验证）**：
1. 晨报弹窗无底板——`#paper` 默认无背景 + `.sk-* #paper` 选择器作用域错（#paper 不在
   #panelSide 内永不命中）。修复：#paper 给默认深色底；皮肤规则改 `#modal.sk-* #paper`，
   openPaper 时把 sk 类挂到 #modal。
2. 皮肤解锁后 tab 仍显示"6 台运转解锁（9/6）"——setLock 未锁时改显"✓ 已解锁"。
3. 残骸态精灵过暗融底（`grayscale(.75) brightness(.6)` 使机器与暗背景不可分）——
   改 `grayscale(.4) brightness(.7)`，锈色隐约可见。

**改进意见（按对带入感的影响排序，多数是 Godot P2 项）**：
1. **机器待机动画 + 环境音未落地**——方案里"没有 NPC，机器的活着就是人气"全靠这条，
   是对标鸭科夫/避难所最大缺口（P2 首位）。
2. **全厅灯光叙事未落地**——底图亮度恒定；规格是"修复一台，主光源亮一档"
   （Godot 用 CanvasModulate tween，半天的活，进度可感的核心）。
3. **Lv2/Lv3 场景不可见**——升级外挂件精灵 ~18 张未生成，升级目前只动数字；
   避难所/鸭科夫的房间升级都有实体变化，这是"升级值得"的关键。
4. **面板皮肤实体图是道具立绘不是 9-slice 框**——T1 画架/T2 机柜/T3 支架带腿，
   不能直接当面板容器框；真 UI 需裁屏面区做 9-slice 或重生成"正视图纯框"版。
   网页 CSS 模拟皮肤是对的过渡形态。
5. **锁定格引导弱**——Godot 版建议加地面修复位标记 + hover 高亮（网页里标签🔒勉强够用）。
6. 小项：电台/分析仪/实验台残骸抠图脚部有白色残絮（泛洪残留，可加形态学清理）；
   多张 active 精灵自带烘焙光晕（电台/分析仪/打印机/充能舱），换底图后会显矩形感，可接受。
