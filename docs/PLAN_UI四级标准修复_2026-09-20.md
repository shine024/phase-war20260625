## R-A 交互硬伤批（可立即开工）

### R-A1 排行榜敌方行死交互 【P0，实锤已复核】

- **现象**：敌方相位师排行榜整列点击无反应，无 hover 反馈。
- **根因**：`scenes/ui/leaderboard/enemy_row.tscn:19` 的 RowButton `mouse_filter = 2`
  （MOUSE_FILTER_IGNORE），事件永不到达；而 `enemy_row.gd:28` 的
  `_button.pressed → row_pressed` 与 `leaderboard_panel.gd:308→323→414` 详情弹窗链
  全部依赖它。自项目初始提交即如此。
- **修法**：
  1. 删除 `enemy_row.tscn:19` 的 `mouse_filter = 2` 一行（Button 默认 STOP 即可）。
  2. 给 RowButton 补 hover 态：在 `enemy_row.gd` `_ready()` 里用
     `PanelStyles.make_roster_item_style(false)` 同族样式挂 normal/hover
     （参照 `scripts/ui/panel_styles.gd:102-114`），或最低限度 theme hover 透出即可。
  3. 行内子 Label 默认 IGNORE 不挡事件，无需处理。
- **验收**：实机打开排行榜→敌方相位师 tab→点击任意行→详情 PopupPanel 弹出；
  hover 时行有视觉反馈。
- **风险**：极低。原事件链代码完好，只是事件进不来。

### R-A2 CardInfoPanel 开板无动画无音效

- **现象**：卡牌/单位详情面板"静默突现"。战场点单位是高频操作。
- **根因**：`scenes/ui/card_info_panel.gd:309-325`（show_card_info）与 `:327-351`
  （show_unit_info）直接 `visible = true`，无 PanelAnim、无 panel_open 音。
- **修法**：两处 `visible = true` 后追加统一开板调用（照抄 main.gd:497-500 的
  `_open_overlay` 内部做法）：
  ```gdscript
  visible = true
  PanelAnim.open(self)
  AudioManager.play_ui_sound("panel_open")   # 以 main.gd 实际调法为准
  ```
  注意 `_position_at` 内有 `await process_frame` 再定位——PanelAnim.open 的弹出位移
  需在定位完成后启动，或把 open 挪到 `_position_at` 之后调用（以实测定序，防弹起点错位）。
- **验收**：背包点卡、战场点单位，面板淡入+弹出+开板音；连点不同单位不叠影
  （复用实例，`PanelAnim` 需幂等——若当前实现不支持重复 open，加 `_is_animating` 守卫）。
- **风险**：低。战场连点单位是高频路径，重点回归"快速连续点击"。

### R-A3 CardInfoPanel 关闭钮三态同款

- **现象**：✕ 关闭按钮 normal/hover/pressed 用同一个 StyleBoxFlat，仅字色灰→白，
  与 PanelChrome 关闭钮"hover 转红"（`panel_styles.gd:446-465`）标准相悖。
- **根因**：`scenes/ui/card_info_panel.tscn:224-226` 三个
  `theme_override_styles/*` 都指向 `SubResource("StyleBoxFlat_close_btn")`。
- **修法**（二选一，推荐 1）：
  1. tscn 内新增两个 SubResource：hover=同底色+红边框 `Color(0.9,0.3,0.3,0.8)`、
     pressed=底色压暗 0.8，替换 :224-226 的 hover/pressed 两行。
  2. 或运行时在 `card_info_panel.gd` `_ready` 里
     `PanelStyles.make_close_button_styles()` 覆写三态（与 PanelChrome 完全同款，
     一致性最好）。
- **验收**：悬停 ✕ 变红/加边，按下有压暗。
- **风险**：极低。

### R-A4 world_map 自建按钮 hover 跳变 / pressed 缺失

- **现象**：三处自建按钮只覆 normal，hover 回退全局主题青色样式（观感跳变）；
  关卡圆钮按下无视觉确认。
- **位置与修法**（全部在 `scenes/world_map.gd`）：
  1. 势力领地图入口 `:288-295`（territory_btn，仅 normal）→ 补
     hover=lightened(0.14)、pressed=darkened(0.1) 两档（duplicate 现有 tbs 改色，
     照 `:1071-1074` 现成写法）。
  2. 返回按钮 `_style_back_button` `:404-414`（仅 normal）→ 同上补两档。
  3. 卡车徽章 `:1418`（仅 normal）→ 同上。
  4. 关卡圆钮 `:1075` `pressed` 直接复用 normal → 改挂
     `sb_pressed = sb.duplicate(); sb_pressed.bg_color = sb.bg_color.darkened(0.12)`。
- **验收**：三处按钮 hover 不再闪变全局样式；圆钮按下有压暗反馈。
- **风险**：低，纯样式。

**R-A 验收流程**：headless 冒烟（无报错）+ 实机过一遍排行榜/卡牌详情/世界地图；
gdunit 全量回归。

## R-B 便捷性补缺批

### R-B1 日常任务一键领取

- **现状**：`scenes/ui/quest_panel.gd:491-503` 每行独立"领取"按钮，7 个任务最多
  7 次点击；`managers/daily_task_manager.gd:254` 只有单任务 `claim_task_reward`。
- **修法**：
  1. `daily_task_manager.gd` 新增：
     ```gdscript
     ## 一键领取全部已完成未领取任务，返回领取数量
     func claim_all_completed() -> int:
         var n := 0
         for task in _daily_tasks:            # 以实际容器字段名为准
             if task["completed"] and not task["claimed"]:
                 task["claimed"] = true
                 _grant_task_rewards(task)
                 n += 1
         if n > 0:
             _save / emit_signal(...)          # 与单领路径同样的持久化与信号
         return n
     ```
     复用 `_grant_task_rewards`（:263），不发新信号名，走既有完成/领取信号。
  2. `quest_panel.gd` 标题/工具行加"一键领取(N)"按钮（对照
     `achievement_panel.gd:24,61-66` 的 ClaimAllButton 结构）：
     - N = completed && !claimed 计数；N=0 时 disabled；
     - 点击后 toast"领取了 N 个任务奖励"（走 ToastManager），刷新行。
- **验收**：完成 2+ 任务→按钮显示数量→一键领→行变"✓ 已领取"、奖励入账、
  按钮置灰；重进面板状态保持（走现有存档字段，无新持久化）。
- **风险**：低。奖励发放复用同一函数，无新经济路径。

### R-B2 快捷键可见角标

- **现状**：keybinds.gd:15-22 六动作 + main.gd:417-421 部署槽 1-9，仅存在于
  tooltip 文字（bottom_function_bar.gd:95-102）与帮助面板；图标上无任何标注。
  文章正面教材正是"图标上标按键字母"。
- **修法**（分两步，第一步先做常显角标，重绑后跟随）：
  1. 新增小工具函数（建议放 `scripts/ui/` 下，如 `keycap_badge.gd`）：
     生成右上角小圆角 Label（10~12px、DT 面板暗底+亮字、黑描边），
     `bind_to_action(action_name)` 显示当前键位文本（`keybinds.get_binding_text()`，
     以 keybinds.gd 实际 API 为准），并连接键位重绑变更信号刷新。
  2. 挂点：bottom_function_bar 四个功能按钮（背包 B/1、成长 7、设置 9、地图 M）
     + bottom_instrument_bar 部署槽 1-9 数字角标（槽位顺序固定，直接静态标注；
     部署槽已有 40px 下限护栏 bottom_instrument_bar.gd:1158，角标放槽右上角不挤卡图）。
- **验收**：实机看底栏按钮与部署槽有角标；设置里重绑后角标文本跟着变；
  大字号模式（1.25×）下角标不溢出按钮。
- **风险**：中低。注意 1-9 部署槽同时被「背包 B/1」共用动作的角标不要重复标 1。

### R-B3 连携/combo 系统首次引导

- **现状**：combo_status_strip.gd 只有常驻 tooltip；不在 FeatureUnlockPopup.show_once
  任何调用点、不在 feature_unlock_schedule.gd 门控表、不在 14 步教程。
  玩家首次看到连携条无解释来源。
- **修法**（最小方案）：
  1. 找到 combo 系统首次生效时机（首次凑成一对同卡连携/首次进阵容第二同名卡——
     以 combo_engine/配卡逻辑实际触发点为准）。
  2. 在该时机 `FeatureUnlockPopup.show_once("combo_intro", ...)`，文案两条：
     连携是什么 + 指向 buff 条悬停可看详情（呼应已有 tooltip）。
  3. `feature_unlock_schedule.gd` 表补一行（关数对齐 combo 实际可用关卡）。
- **验收**：新档首次触发时弹一次说明；旧档已过该时机但从未弹过的玩家
  （user:// 无该 key）下次触发也补弹一次；二次进游戏不再弹。
- **风险**：低。show_once 体系现成（feature_unlock_popup.gd:17-27）。

## R-C 包容性批

### R-C1 超宽屏战场裸屏 【观战游戏核心画面】

- **根因**：阵型带硬编码 `BATTLE_X0=40/BATTLE_X1=1240`（`scripts/card_grid_battle_layout.gd:17-18`，
  消费方 battle_slot_grid.gd:14、battlefield_ambience.gd:25）+ 战场背景
  1280 宽锚 x=0 不拉伸（`scenes/battlefield/battlefield.gd:41/605` 及
  `_apply_background_texture` 的 `position=Vector2(0,…)`）。
- **修法**：
  1. 背景铺满：`_apply_background_texture` 改为按 `get_viewport_rect().size.x`
     等比放大宽度（保纵横比裁纵向或三段平铺，以背景图实际构图为审定），
     `centered=false, position.x = (viewport_w - scaled_w) * 0.5` 居中。
  2. 阵型带展开：`card_grid_battle_layout.gd` 的 X0/X1 不再是常量，改
     `static func band(viewport_w)` 返回居中带（≥1280 时向两侧扩，<1280 维持
     现有 40..1240 clamp），消费方改传视口宽。
  3. 前景装饰（battlefield_ambience）同步用同一 band 函数。
- **验收**：窗口拖成 21:9（2560×1080）与 32:9，双方阵型居中、背景铺满无裸屏；
  16:9 与 16:10 与改造前逐帧对比无位移（回归红线：**16:9 布局像素级不变**）。
- **风险**：中。战场是核心场景，需实机多分辨率截图对比；建议先做背景铺满
  （低风险），阵型带展开单独一步验证。

### R-C2 满血 HP 数字停止淡化

- **根因**：`scenes/units/unit_hp_bar.gd:83` `IDLE_FADE_ALPHA=0.45`，`:397-399`
  把 `_hp_label` 一并列入 modulate.a 衰减列表——开局全场满血时 HP 数值低对比，
  而 HP 白字黑描是敌我识别兜底通道之一。
- **修法**：从淡化列表中移除 `_hp_label`（血条图形本体保留淡化省注意力）；
  若视觉上嫌数字太跳，可给数字单独较高 alpha（如 0.75）而非全亮。
- **验收**：满血时 HP 数字清晰可读；掉血/回血动效不变。
- **风险**：极低，战场所有单位常驻渲染，留意批量 modulate 改动不影响性能
  （本改动只减少一个衰减对象）。

### R-C3 COLOR_TEXT_FAINT 提亮一档

- **根因**：`resources/design_tokens.gd:204` (0.27,0.31,0.39) 对卡底 #131a2a
  约 2.1:1（WCAG 文本要求 4.5:1），承载功能信息 22 处（商店售罄名、情报未拥有项、
  卡牌次要字段）。
- **修法**：提亮到对比度 ≥4.5:1 的相邻值（目标约 (0.45,0.50,0.58) 一带，
  以实际算式核算为准）；同 token 单点改，22 处消费自动生效。
- **验收**：商店售罄/情报未拥有项文字可读仍明确"弱于正文"的层次；
  ui_p1/ui_batch2 校验脚本不因色值断言失败（若有断言需同步更新）。
- **风险**：低，但要过一眼 22 处消费场景的层次感（弱信息不能反客为主）。

### R-C4 战斗内最小字号下限

- **根因**：状态层数 6px（unit_hp_bar.gd:552-560 draw_string）、战力/档位 9px 且用
  FAINT 色（geo_shapes.gd:189-198）；1280×720 基准下肉眼极限，且 draw_string
  不吃 content_scale_factor（大字号模式救不了）。
- **修法**：6px→8px、9px→11px 起步（配合 R-C3 的 FAINT 提亮）；层数数字若在
  8px 下溢出状态图标，改画在图标右下角小圆片上。
- **验收**：1080p 与 720p 窗口下层数/战力可读；同屏 20+ 单位无文字糊版。
- **风险**：中。战斗 UI 密度高，需实机满屏单位截图核对。
