# 竞品反思修订计划（2026-09-19）

> **依据**：`docs/竞品评价采集/README.md`（1680 条 Steam 竞品评论分析；数据层与第七节代码事实已逐条核实）。
> **目标**：把竞品差评教训映射为 Phase War 可执行修订。三大原则来自数据：①RNG 公平感 > 深度本身；②最毒差评来自 200h+ 老玩家长线劣化；③纯离线是本作天然优势。
> **执行须知**：文中行号为 2026-09-19 快照，执行前先重新定位（代码会漂移）；每项验收标准是硬门，不满足不算完成。

## 批次总览

| 批次 | 内容 | 性质 | 规模 |
|---|---|---|---|
| P0 | 文档口径修正 + 发行宪法起草 | 纯文档 | ~0.5 天 |
| P1 | 概率可见化（pity/黑门/相位师规则上 UI） | UI + 文案 | 2~3 天 |
| P2 | 新手情报引导 + 埋点闭环 | 教学 + 埋点 | 2~3 天 |
| P3 | 长线验收 + 发行工程前置 | 验收清单 + 排期 | 1~2 天（不含执行） |

**范围红线（本计划全程有效，任何任务不得违反）**：
- 不引入任何 IAP / 广告 SDK（现状为零，保持为零）。
- 不重做随机系统——现有 pity/驻守制/递增保底已对症，本计划只做"让玩家看见"。
- 多语言本计划只做选型 + 排期登记，不做全量翻译。

## P1 概率可见化（近期，竞品负面第一大类对策）

> 原则：机制都在且质量不错，缺的只是"玩家看得见"。三处口径上 UI，文案数值一律从常量读取，禁止硬编码。

### T1.1 制造 pity 口径展示
- **背景**：pity 机制存在（`managers/manufacture_manager.gd:315-319` 出 rare+ 清零否则 +1；`:527-536` 随机箱 legendary+ 同机制；`:397-412` 晶体垫 pity `CRYSTAL_PER_PITY := 80`）但玩家不可见。
- **改动点**：
  1. 执行前先读 `manufacture_manager.gd` 确认各保底**阈值数值**（多少次必出），此数值当前未核实，不得凭空编。
  2. 在制造面板（改造箱/随机箱购买处）增加保底进度提示：当前计数 + 保底线。
  3. 晶体垫处显示推进计数口径（~~"每 80 晶体必出稀有+"~~ **2026-09-20 勘误：实为每 80 晶体推进保底计数 1 次，软保底无必出，且垫至激活线前封顶**——原"必出"表述违反本条自身"不得凭空编"规则）。
- **验收**：玩家在购买前能看到保底进度（~~"还差 N 次必出"~~ **2026-09-20 勘误：保底为概率 ×2 软提升、无必出，落地文案为"保底 N/3（还差 X 次）…概率 ×2"**）；文案数值引用常量；`tests/` 下有对应单测（文案生成函数级即可）。

### T1.2 黑门规则页
- **改动点**：黑门入口 UI 增加/充实规则说明：每日免费 3 次（`FREE_ENTRIES_PER_DAY`）、能量块加次 60/次（`ENERGY_PER_EXTRA_ENTRY`）、周榜重置时间。数值读常量。
- **验收**：入口处一屏内可见全部规则；改常量文案自动跟随。

### T1.3 相位师遭遇规则展示
- **背景**：这是反思 #1（随机可情报化）的核心展示面。现状：驻守 100%、非驻守 15% + 递增保底，玩家只能靠猜。
- **改动点**：
  1. 在情报系统 UI（`scripts/systems/intel_discovery_manager.gd` 相关面板）增加"相位师情报"分区：基础遭遇率、驻守关固定遭遇、递增保底机制说明。
  2. 递增状态若可查询（`game_manager.gd:60-93` 的计数），显示"连续 N 关未遭遇，下次概率 X%"——这是"随机可准备"卖点的最强证明。
- **验收**：新手保护期结束前后各有一次自然的情报触达；数值读 `game_constants.gd`。

## P2 新手引导与埋点闭环（近期）

### T2.1 情报系统前 2 小时讲透
- **背景**：情报系统是差异化主打，但新玩家前 2 小时摸不到（Mechabellum 150h 入门教训的反面做法）。
- **改动点**：
  1. 在 v32.3 教学链（`scenes/bunker/truck_base.gd:2697` 起的前移教学）中植入一个节点："遭遇相位师 → 打开情报 → 使用对策"，跟随第一次相位师遭遇触发。
  2. 新手保护期（前 10 关）结束前，用一次性提示预告"遭遇率将开始出现，情报可化解"。
  3. `build_advisor`（`data/build_advisor.gd`，`world_map.gd:2191` 调用）的战前建议覆盖"本关可能遭遇相位师"的场景。
- **验收**：不开 debug 从头玩，前 10 关内能自然学到"随机可情报化"这一句话；教学节点可跳过不强制。

### T2.2 "流派成型时刻"埋点
- **背景**：新手验收不能自嗨，要有数据判据。
- **改动点**：在 `managers/performance_metrics_manager.gd` 增加事件：首次激活套装、首次完成 12 套装任一组合、首次 mythic、首次通关相位师驻守关——各带时间戳（游戏内时长）。
- **验收**：事件入埋点管道并可在本地日志读出；判据写进 `docs/` 试玩验收清单：**新档 2 小时内至少触发 1 个成型事件**。

### T2.3 观战体验判据埋点
- **背景**：B1 已实现（倍速 `battle_spectacle.gd` B1-1 ×4 档/极速推演、观战 B1-2、战报 B1-3）；README 反思 #8 的判据"倍速+跳过使用率 >70% ⇒ 回炉"未落进管道。
- **改动点**：埋点记录倍速档位使用分布与跳过率（战斗结束按场次聚合）。
- **验收**：能从埋点数据直接算出"倍速+跳过使用率"；70% 判据写入试玩验收清单。

## P3 长线验收与发行工程前置

### T3.1 后期节点专项验收清单
- **背景**：最毒差评全部来自 200h+ 老玩家（背包乱斗 267h、Melvor 268h）"长线劣化"；毕业期（249 改造 ×12 套装 + mythic + 周榜）从未专门验过。
- **改动点**：新建 `docs/试玩验收_长线节点.md`：
  1. 定义 20h / 50h / 100h 三节点检查表：毕业感 vs 数值膨胀感、每日目标还剩几个、改造收集完成度曲线。
  2. 附"跳进度"实测方法：用 debug 存档构造三节点进度档（说明用 SaveManager v9 格式手工构造或现有 debug 工具），逐项人工过表。
- **验收**：清单存在且完成一轮实测记录（可另行排期执行，但文档与工具本批完成）。

### T3.2 多语言排期 + 技术选型 spike
- **背景**：竞品数据本地化差评 0 = 行业标配；现状零翻译系统、全硬编码中文（数据层有 `name_en` 备胎字段，如 `data/modification_modules/enhancement_mods.gd:66`）。
- **改动点**（本批只做选型，不做翻译）：
  1. 写 `docs/发行壳_多语言选型.md`：对比 Godot CSV translation 工作流 vs 运行时替换方案，给出推荐与迁移成本估算（重点：UI 硬编码中文的提取方式、数据层 name_en 字段利用率）。
  2. 在发行壳批次计划（`docs/定位转向_战术构筑放置_2026-09-14.md` 第四节）正式登记多语言条目与排期。
- **验收**：选型文档有结论；发行壳计划含多语言条目。

### T3.3 纯离线卖点落地
- **改动点**：
  1. 发行素材任务登记（`_steam_assets/` 目录已有）：商店页短描述明示"100% 离线可玩 / 存档在本地"。
  2. 发行壳批次决策项：Steam Cloud 启用与否——若启用必须做冲突处理验收；若不启用，商店页标注"本地存档"。登记进发行壳计划。
- **验收**：两个决策项出现在发行壳计划文档，带勾选框。

### T3.4 路线图草案与 tag 纪律
