Section 02

问题诊断

按严重程度排序，从阻断性 bug 到体验细节逐一列出。

🐛
调试信息泄露到正式界面
Debug overlay visible in production UI
P0 · 阻断
  • 顶部出现 输入、2D/3D 切换、1280×720 分辨率显示等 Godot Editor 调试栏元素
  • 第 100 关文字直接浮在天空背景上，无背景面板，几乎不可读
  • 改造模块库中直接显示代码变量名：crit_mark_chance: 0.3、slow_aura: 0.4、ally_fort_regan: 0.5（还有拼写错误 regan→regen）
  • 中心面板出现橙色 F- 占位方块，明显是缺失贴图的 debug 图标
影响截图：①⑦⑨ 顶部调试栏；③ 代码变量名泄露；⑦ 中心橙色占位图
🎨
美术风格严重割裂
Art direction inconsistency across screens
P0 · 风格冲突
  • 奇幻 vs 科幻：卡牌使用华丽金色雕花边框（奇幻 RPG 风格），但整体 UI 是深色科技风（赛博朋克/军事科幻）。两种风格无法共存
  • 扁平 vs 拟物：底部导航栏是纯扁平现代 App 风格，而卡牌边框是厚重金属浮雕。同一产品中同时出现两套设计语言
  • 像素 vs 矢量：部分图标是像素风，部分是矢量扁平图标，质感不统一
  • 背景 vs UI：战场背景是厚涂油画风沙漠日落，UI 却是冷色半透明科技面板，两者完全不在一个世界观里
影响截图：全部 9 张。卡牌的金色雕花边框与深色科技 UI 形成最强烈的风格冲突
🌈
配色体系混乱，缺乏统一语义
No consistent color semantics
P1 · 高优
  • 稀有度颜色无规范：卡牌边框使用金/蓝/银/紫/橙/粉/黄等多种颜色，但不同截图中同一颜色代表的含义不一致
  • 强调色过多：青色、紫色、橙色、绿色、黄色同时作为强调色出现，没有主次之分
  • 状态色不统一：绿色既用于"可安装"，又用于资源数值，还用于 Buff 文字；红色既用于伤害数字，又用于通知红点
  • 选中态过激：相位仪界面中选中项使用荧光绿边框+荧光绿文字，视觉攻击性太强，与整体暗色调冲突
影响截图：②③④⑤⑥。特别是 ⑤ 中荧光绿选中态和 ④ 中六种边框颜色无图例说明
📐
布局结构不统一
Inconsistent layout patterns
P1 · 高优
  • 弹窗尺寸差异大：战斗卡阵列、改造库、符文图鉴都是大弹窗，但尺寸、圆角、边框厚度各不相同
  • 三栏 vs 双栏 vs 单栏：强化站用左中右三栏，成长中枢用左栏+右侧 2×2 网格，改造站又变成三栏但右侧大面积空白
  • 底部导航固定但内容区不固定：12 个图标始终在底部，但上方内容区的宽度、边距、对齐方式因页面而异
  • 空白区域浪费：战斗卡阵列右侧有大片黑色空白，改造站右侧面板几乎为空
影响截图：②⑥⑦⑧。改造站右侧大面积空白尤其明显
🔤
中英文混排与本地化不完整
Mixed localization and incomplete translation
P1 · 高优
  • 标题双语格式不统一：有的用 中文 · ENGLISH（如"战斗卡阵列 · COMBAT ROSTER"），有的只用英文（如"GROWTH COMMANDO"），有的只有中文
  • 代码变量泄露：改造库中 crit_mark_chance: 0.3 应显示为"暴击标记概率：30%"
  • 大小写不统一："Lv."、"MAX"、"★7"混用；"rare"出现在中文界面中
  • 拼写错误：ally_fort_regan 应为 regen
影响截图：③④⑤⑥。改造库的代码变量是最严重的本地化问题
📏
字体层级与可读性问题
Typography hierarchy and readability
P2 · 中优
  • 字号梯度不足：标题、正文、辅助文字的字号差距太小，缺乏清晰的信息层级
  • 低对比度文本：搜索框占位符、过滤标签、顶部关卡文字在深色背景上对比度不足
  • 卡片内文字过小：卡牌名称、属性描述在网格中难以快速扫描
  • 底部导航图标过小：12 个图标挤在一行，触控目标太小
影响截图：全部。特别是 ② 卡牌网格中的小字和 ⑨ 底部导航
↔️
间距与对齐不规范
Inconsistent spacing and alignment
P2 · 中优
  • 无统一栅格系统：各页面的边距、列宽、卡片间距没有遵循同一套规则
  • 卡片网格密度不一：有的 3×7，有的 6 列，有的单列列表，没有统一的网格基准
  • 按钮对齐偏差：成长中枢底部三个操作按钮未居中对齐，略有偏移
  • 滚动条样式不统一：有的使用原生滚动条，有的自定义，视觉风格不一致
影响截图：⑥⑦⑧。成长中枢底部按钮偏移和改造站右侧空白
⚠️
信息密度过高，认知负担重
Information overload
P2 · 中优
  • 顶部区域堆叠过多：标题、进度、搜索、过滤、子标签全部压在同一小块区域
  • 状态面板信息过载：左上角同时显示战斗状态、资源、Buff 列表，文字层叠在背景上
  • 卡片信息过密：相位仪卡片同时展示星级、名称、阵营、6 项数值、被动技能、主动技能
  • 缺少折叠/渐进展示：所有信息一次性展开，没有"先看概览，再深入详情"的层次
影响截图：⑤⑥⑨。相位仪卡片的信息密度最高
🧭
导航与交互反馈不明确
Unclear navigation and interaction feedback
P2 · 中优
  • 底部 12 个图标无主次：当前页面高亮不够明确，用户难以判断自己在哪
  • 右下角控制按钮像播放器：播放/暂停/旗帜/返回四个彩色方块缺乏明确语义
  • 筛选器重复：顶部横排筛选和左侧竖排筛选有重叠，且数量不一致（如 ③ 中顶部有"炮兵/侦察"但侧栏没有）
  • 空状态无引导：改造站右侧面板为空时没有提示如何操作
影响截图：③⑧⑨。改造站右侧空白和右下角播放器式按钮

统一使用渐变边框，废弃金色雕花/银色金属等奇幻风格边框。所有稀有度颜色必须与边框+光效+图标风格保持一致。

🔄 配色问题 → 解决方案

当前问题
  • 荧光绿选中态过于刺眼
  • 稀有度颜色超过 6 种且无图例
  • 金色雕花边框与科技 UI 冲突
  • 青色滥用导致重点不突出
  • 红黄蓝绿四色底部按钮像播放器
优化方案
  • 选中态使用主强调色青色 + 柔和光晕
  • 稀有度统一为 4 级渐变，附图例
  • 边框改为简洁科技线条+稀有度发光
  • 青色仅用于关键数据和选中态
  • 底部控制统一为单色图标按钮

布局规范优化方案

建立统一的页面结构模板，减少每个页面的独特性，提升产品整体感。

📐 统一页面模板

模板 A：列表 + 详情（适用于 改造库/符文/相位仪）
左侧筛选栏 (240px) | 右侧内容网格/列表 | 顶部统一工具栏
模板 B：三栏操作（适用于 强化/改造站）
左侧单位列表 | 中间详情+操作 | 右侧进度/路径
模板 C：弹窗选择（适用于 卡阵列/图鉴）
居中弹窗 (最大 90vw) | 顶部搜索+筛选 | 网格内容 | 底部操作栏
模板 D：战斗界面（适用于 战场）
全屏战场 | 左上信息面板 (可折叠) | 底部手牌+导航

Section 08

实施路线图

按优先级分三个阶段推进，每阶段解决一类核心问题。

阶段 优先级 问题 具体行动 预计影响
Phase 1 P0 调试信息泄露 隐藏 Godot Editor 调试栏；移除代码变量显示；替换占位贴图 消除所有开发痕迹，界面不再像 alpha 版本
Phase 1 P0 美术风格割裂 确定单一视觉方向（建议：军事科幻 + 简洁科技线条）；废弃金色雕花边框 产品整体感大幅提升，风格统一
Phase 2 P1 配色体系 建立语义色彩规范；统一稀有度 4 级配色；限制强调色数量 用户能更快理解颜色和状态的对应关系
Phase 2 P1 布局结构 定义 4 套页面模板；统一弹窗尺寸/圆角/阴影；修复空白区域 各页面之间视觉连贯性显著改善
Phase 2 P1 本地化 全部代码变量替换为中文化描述；统一中英混排格式；修复拼写错误 专业度提升，不再暴露开发内部信息
Phase 3 P2 字体与间距 建立字号层级；统一 4px 栅格系统；提升文字对比度 阅读舒适度改善，信息层级更清晰
Phase 3 P2 导航优化 精简底部导航；明确当前页面指示；重构战斗控制按钮 导航效率提升，误触减少
