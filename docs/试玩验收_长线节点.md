# 试玩验收：长线节点专项（2026-09-19 立项）

> **来源**：`docs/竞品反思修订计划_2026-09-19.md` T3.1。
> **背景**：竞品最毒差评全部来自 200h+ 老玩家（背包乱斗 267h、Melvor 268h）的"长线劣化"；
> 本作毕业期内容（249 改造 ×12 套装 + mythic + 黑门周榜）从未专门验收。本清单把
> 20h/50h/100h 三节点变成可执行检查表，防"新手验收自嗨、老玩家默默流失"。

## 一、成型时刻判据（新档验收，<2h）

**数据源**：试玩构建（custom feature `pw_playtest`）的 `playtest_metrics.json`
→ `snapshot.milestone_events`（v6.19 P2-T2.2 落地；v6.19.1 核验修正：**跨会话持久**
`user://milestones.cfg`，重启不重记"首次"；时间戳 `total_ms` = 累计游戏内时长）。

| 埋点名 | 语义 | 触发点 |
|---|---|---|
| `combo_active_first` | 首次激活任一套装（备战或战斗内） | bottom_instrument_bar / combo_engine |
| `combo_full_first` | 首次完成任一套装满档组合 | 同上 |
| `first_mythic_mod` | 首次获得神话档改造（开箱/安装） | manufacture_manager / blueprint_manager |
| `first_mythic_card` | 首次制造出神话档卡（满池专属，v6.19.1 补） | manufacture_manager.manufacture |
| `first_garrison_clear` | 首次通关相位师驻守关 | game_manager 结算 |
| `first_phase_master_encounter` | 首次遭遇相位师（驻守/随机） | game_manager |

**硬判据**：新档 2 小时内至少触发 1 个成型事件（按 total_ms 累计口径）。零触发 ⇒ 前期节奏回炉（改造/制造解锁门槛、掉落权重优先排查）。

## 二、观战体验判据（倍速+跳过使用率）

**数据源**：`snapshot.event_counters` 的 `battles_total` / `battles_spedup` / `battles_skipped`
/ `battles_sped_or_skipped`（v6.19 P2-T2.3 场次聚合；`speed_x2/x3/x4`/`skip_activated`
保留为次数口径）。

**口径**（v6.19.1 闭合）：使用率 = `battles_sped_or_skipped / battles_total`
（一场同时用倍速+跳过只计 1——联合计数器直接可读，无需自行算并集）。

**硬判据**（承 README 反思 #8）：使用率 > 70% ⇒ 演出/节奏没做够，回炉 B1 观战体验批。
反向判据：使用率 < 10% 且差评/流失样本出现"战斗太慢" ⇒ 倍速入口可见性问题。

## 三、20h 节点检查表（成长中期）

- [ ] 每日目标还剩几个？（挂机/黑门/改造升级/制造——若玩家"上线无事可做"即预警）
- [ ] 改造收集完成度曲线：见过/可造/已装三档比例（情报舱+改造面板人工读数）
- [ ] 套装体系：是否已有 ≥2 个 full 档组合？12 套装中玩家接触过几个？
- [ ] 数值膨胀初兆：同 era 卡战力 top10 vs 主力阵容差距是否失控
- [ ] 相位师遭遇体感：递增保底是否让"久不遇→必遇"可感知（情报舱状态行核对）

## 四、50h 节点检查表（毕业前夜）

- [ ] epic+ 随机箱开出率体感 vs 情报舱展示口径一致（宪法 C3：可见=实际）
- [ ] 晶体垫/黑门加次两个 sink 的使用率（若零使用=定价或引导失败）
- [ ] mythic 持有量与配装渗透（有人装上 mythic 了吗，还是囤图纸？）
- [ ] 周榜参与意愿：黑门 run 次数/周是否衰减
- [ ] "数值膨胀感"访谈：老玩家主观是否有"练了白练"

## 五、100h 节点检查表（毕业期——竞品差评雷区）

- [ ] 毕业感 vs 数值膨胀感二选一访谈（Melvor 268h 差评核心：后期目标真空）
- [ ] 249 改造收集进度与"还差多少"的心理预期
- [ ] 黑门周榜是否支撑每周回归（唯一活榜 survival_highscore 的提交曲线）
- [ ] 驻守关重复可玩性（100 关后的内容锚点还剩什么）
- [ ] 长线存档健康：SaveManager v9 迁移链在 100h 老档上无报错

## 六、跳进度实测方法（构造三节点进度档）

> 原则：不靠真玩 100h——用 debug 存档直接构造节点状态，人工过表。

1. **档位来源**：SaveManager v9 schema（`user://save_slot_%d.json`，3 槽；
   字段以 `managers/save_manager.gd` 各 manager `save_state()` 为准——
   关键段：LevelProgressManager 星级表 / BasicResourceManager 四资源 /
   IntelItemBag 图纸库存 / BlueprintManager pity / ManufactureManager mod_box_pity / Blackgate 周键）。
2. **构造步骤**：
   - 正常开档打到 L10 存档 → 复制为基线档（含合法 schema 头与版本号，勿手拼新文件）。
   - 在基线档上按节点批量改：星级表灌到目标关（20h≈L30 / 50h≈L60 / 100h≈L100+黑门）、
     资源给到节点水位、图纸库存按收集度百分比灌。
   - 载档进游戏，跑一遍迁移链确认无报错（save_manager 控制台输出）。
3. **快速通道**：`GameConfig.debug_no_deploy_limits` 等调试开关可在节点档上加速过表；
   过表结果按第三节~第五节逐项记录。
