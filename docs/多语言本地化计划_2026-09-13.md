# 多语言本地化计划（2026-09-13）

> 结论先行：**中文单语言不阻塞 1.0 正式发行**；英文是性价比最高的第二语言，规划为 1.0 之后的第一个独立内容轮。
> 本文档是 RELEASE_ROADMAP（发行路线图）.md **决策点 D3「语言范围」**的决策依据与执行路线。D3 原文："仅中文 / 加英文；英文版=65+ UI 面板文本外化，独立工程（M~L）"。**本文档给出的建议答案是：仅中文发行 1.0 + 英文作为发行后补丁，D3 最终拍板由用户确认。**

## 一、结论与原则

1. **1.0 以简体中文单语言上线**：RELEASE_GAP_1.0_2026-09-12.md 既定计划不变，不插入本地化工作。Steam 完全允许单语言发行，国区是策略卡牌的核心盘，先发中文拿评测和愿望单数据。
2. **商店页先行双语**（运营层，与游戏本体解耦）：成本低收益高，详见阶段 2。
3. **英文补丁 = 1.0 后第一个独立内容轮**，按商店页数据触发，不是 1.0 前置条件。
4. **语言优先级**：策略卡牌类在 Steam 的盘子里 英 > 俄/葡(巴西)/西/日 > 其他。第二梯队看英文补丁后的评测/销量数据再定，不一次性铺开。

## 二、现状核查（2026-09-13 实测）

| 项目 | 现状 | 对本地化的影响 |
|---|---|---|
| i18n 基础设施 | **零**：全项目无 `TranslationServer` / `tr()` 调用 | 英文补丁需先建翻译资源管线 |
| 文案分布 | 中文字符串硬编码于 GDScript（data-as-code 主体 + UI 逻辑散点） | 大头工作量在字符串抽取 |
| 规模 | `data/` + `managers/` + `scripts/` + `scenes/` 四目录约 **3.67 万行含中文**（含注释；玩家可见文案估计几千条） | 抽取是一个独立轮次（估 1–2 周），非顺手改 |
| 字体 | 打包 Noto Sans SC（含拉丁字形，字体本身无需更换） | 宽度度量按 CJK 校准，需按英文重测 |
| 名牌/排版 | short_name 76 条经 Noto 真字体实测（62px 上限）；名牌条宽 = 卡宽 ×1.12 | 英文字符串普遍变长 → 名牌条/按钮/HUD chip 重测重排 |
| 卡图 | AI 生成位图 512×512 立绘为主 | 需逐批检查是否内嵌文字（立绘预计无字，重点查徽章/特效图/store 截图） |
| 术语底子 | `docs/统一化/LANGUAGE_BIBLE.md` 权威词汇表 | 直接翻译即英文 glossary，不用从零做术语表 |

## 三、三阶段路线

### 阶段 1：1.0 中文先行（现在 → 1.0）
- 不写任何 i18n 代码、不建翻译脚手架（避免为未拍板的补丁预付结构成本）。
- 唯一要求：守住第四节"纪律要求"两条。

### 阶段 2：商店页双语（1.0 上线前后，随时可做）
- Steam 商店描述双语（一句话简介 + 正文 + 标签）。
- 商店截图：用现有 Steam 采集管线（`tests/_tmp_steam_cap.gd`）出中文版；英文版截图待英文补丁落地后补拍。
- 商店页语言选项勾选英文，**正文写明"游戏内容当前为简体中文"**——管理预期、保转化，避免差评轰炸。

### 阶段 3：英文补丁（1.0 后，按数据触发）
**触发决策点（建议参考值，最终由用户拍板）**：商店页上线后英文区愿望单/评测占比可见且持续有英文区流量 → 启动；时机避开 1.0 后的紧急修复期，作为独立轮次排期。

## 四、纪律要求（从现在起执行，成本最低的准备）

1. **文案集中管理**：新面板/新任务/新词条的文案集中到 data 层字典结构（项目本来的 data-as-code 模式，保持纪律即可），不散落写死在 UI 逻辑的 `if/else` 里——集中一条 = 将来抽取一条。
2. **术语一致**：中文文案写作遵守 `docs/统一化/LANGUAGE_BIBLE.md`（本就是统一化双宪法要求）——术语一致让翻译成本直接砍半。
3. 除上述两条外，现阶段**零代码改动**。

## 五、英文补丁实施路径（启动时展开为独立执行计划）

1. **抽取轮**：写批量抽取脚本扫 data 层字典 + UI 硬编码字符串 → 生成 CSV；键直接用现有 id（card_id/quest_id/mod_id 全英文，天然翻译 key）。
2. **管线**：Godot 4.5 CSV → TranslationServer 体系；语言切换入口放设置面板。
3. **排版回归**：`tests/_tmp_measure_names.gd` 流程按英文重跑（62px 上限逐条复测，ASCII 宽字母按 0.52em 估会漏，必须真字体实测）；名牌条/按钮/HUD chip 宽度复核。
4. **美术检查**：逐批过 `assets/card_icons/` 与 `assets/ui/instruments/`；有内嵌文字的图按语言出分版；store 资产另拍英文版。
5. **翻译**：以 LANGUAGE_BIBLE 术语表的翻译版为 glossary；先做玩家高频可见面（卡名/任务/教程/UI 框架文案），低频长尾（help 面板正文等）后补。
6. **验收**：全量 GdUnit + 实机目视英文界面（重点：名牌截断、按钮溢出、教程步骤文案、数字与单位格式）。
