## 0. 依据与前提

**理论依据**（知乎《独立游戏不重视UI设计的后果有多灾难？》，PDF 存 docs/，要点已沉淀进 ui-review skill）：

- 四要素优先级：**便捷性 > 易用性 > 包容性 > 美观性**，冲突时砍低保高
- 提示分层选型：**能 Toast 不用 Tips，能 Tips 不用 Modal**
- 两个提前预见：多物品同时获得的聚合提示、新功能首解锁的一句话 Modal
- 终极验收法：**拿给不玩游戏的人看，他看懂了才算成功**

**执行铁律**（沿用批次二流程，每批必走）：

1. 改前查 ui-review 技能"接入点地图"，能复用不新造；
2. 颜色/字号走 `DesignTokens`，样式走 `PanelStyles` 工厂，禁止新增字面量；
3. 每批跑 `tests/ui_p1_validation.gd` / `ui_batch2_validation.gd`（新文件加进 CHANGED_SCRIPTS）
   + `tests/ui_unified_check.gd`，全绿才收批；
4. 肉眼验收五问：悬停有说明？点击有反馈？失败给原因？ESC 逐层退？换分辨率不破版？
5. CHANGELOG 记批次 + 本计划勾选。
