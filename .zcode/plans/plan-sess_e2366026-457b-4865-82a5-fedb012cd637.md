# 相位师技能树 + 自动经验升星 + 删强化② + 进化改技能树解锁

## 决策汇总（已与你确认）

| 决策 | 内容 |
|------|------|
| 强化②（选词条） | **删除**（card_enhancement_manager + card_enhancement_panel + module_slots） |
| 强化①（纯纳米手动） | **保留不变**（enhance_level 字段、apply_reinforcement、战斗乘区） |

## 架构设计

### 核心：相位师技能树（新建，参照 faction_skill_tree 范式）

**数据层** `data/phase_master_skill_tree.gd`（新建）
```gdscript
extends RefCounted
class_name PhaseMasterSkillTree

# 节点结构（复用 faction_skill_tree 字段 + 扩展）
# id, name, desc, branch(指挥/智能化/火力/概念武器), tier(0-10), cost(技能点),
# requires(前置节点id列表), unlocks(解锁内容描述), effects(效果字典)
const SKILL_TREE: Dictionary = {
  "command": [   # 指挥分支：单位上限/光环/部署/特殊卡
    {...}
  ],
  "intelligence": [  # 智能化分支：自动行为/AI加成/经验加成/affix赋予
    {...}
  ],
  "firepower": [  # 火力分支：三维攻击/暴击/穿甲/射程/概念武器小技
    {...}
  ],
  "concept_weapon": [  # 概念武器分支：核子轰炸/酸雨/能量罩等大技
    {...}
  ],
}
```

**解锁类型**（`unlocks` 字段，驱动不同子系统）：
- `{"type": "phase_instrument", "id": "pi_steel_01"}` → 调 PhaseInstrumentManager.unlock_instrument
- `{"type": "unit_ability", "id": "light_crit"}` → 兵种特殊能力（原 enhance 等级解锁的，现挪这里）
- `{"type": "unit_mechanism", "id": "recon_vision"}` → 新兵种独占机制（侦察视野/工兵建造等）
- `{"type": "concept_weapon", "id": "nuclear_bombardment"}` → 概念武器大技（从相位仪 active_ability 抽出）
- `{"type": "special_card", "id": "some_card_id"}` → 特殊卡解锁
- `{"type": "evolution", "target_id": "ww1_inf_advanced"}` → 进化解锁（替代进化门槛系统）
- `{"type": "affix", "pool": [...]}` → affix 词条池赋予

**管理器** `managers/phase_master_skill_manager.gd`（新建）
- `unlock_node(node_id)` / `can_unlock_node` / `get_active_effects` / `is_unlocked`
- 技能点来源：相位场 XP 升级（复用现有 grant_phase_field_xp 的 PHASE_FIELD_POINTS_PER_LEVEL）
- save_state/load_state 注册到 SaveManager

### 自动经验升星（新建）

**经验字段** `resources/card_resource.gd:152` 后加：
```gdscript
var battle_experience: int = 0   # 战斗经验，达阈值自动升 star_level
var star_level: int = 0           # 自动升星等级（0-9，与 enhance_level 独立）
```
注：star_level 是新字段，**不影响现有 enhance_level**（强化①保留）。star_level 驱动 affix 加成（替代原 on_blueprint_star_up 的随机触发）。

**经验阈值** `data/battle_experience_config.gd`（新建）：
```gdscript
const STAR_EXP_THRESHOLDS = [0, 100, 250, 500, 900, 1500, 2400, 3800, 6000, 9500]  # 0-9星
const BATTLE_WIN_EXP_BASE = 50      # 每场胜利基础经验
const BATTLE_KILL_EXP = 5           # 每次击杀经验
```

**经验接入点**（修改）：
- `scripts/signal_bus.gd`：新增 `battle_experience_granted(instance_ids: Array, amount: int)` 信号
- `managers/game_manager.gd` `_on_battle_ended`：战斗胜利时，计算总经验 = `BATTLE_WIN_EXP_BASE + kills × BATTLE_KILL_EXP`，平分给上场存活卡的 instance_ids，emit 信号
- `managers/instance_registry.gd`：新增 `add_experience(instance_id, amount)` → 累积到实例的 battle_experience，达阈值自动 star_level += 1 → emit `card_star_up`

## 关键设计决策

1. **star_level 与 enhance_level 并存**：star_level（自动升星，驱动 affix）与 enhance_level（手动强化①，驱动战斗乘区）是两个独立成长轴。玩家既能手动投入纳米强化①，也能靠战斗经验自动升星获得 affix。避免破坏现有战斗平衡。

2. **技能点来源**：复用相位场 XP 升级（`grant_phase_field_xp` 已有 `PHASE_FIELD_POINTS_PER_LEVEL=1`），现每级给的可分配点从"相位场 4 维"改为"技能树技能点"。相位场 4 维属性点保留（继续驱动 atk/def/hp/energy_pct）。

3. **向后兼容**：
   - module_slots 字段保留（旧存档读取不崩，但不再写入）
   - enhancement 存档字段读取时忽略（不崩）
   - 相位仪 unlock_instrument 入口复用，旧解锁状态保留

4. **技能树节点数据先行**：阶段 1 先建 4 分支骨架（每分支 5-8 个代表性节点），阶段 6 再逐步填充全部节点内容。避免一次性写完所有节点导致无法验证。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 一次性改动 30+ 文件，易引入连锁错误 | 内部 6 阶段，每阶段后 check-only + grep 验证 |
| 战斗平衡（删 module_slots 加成后单位变弱） | module_slots 加成本就小（v6.x 后主要靠 enhance_level + 改造），影响可控 |
| 进化门槛改技能树后旧存档卡住 | 进化面板加"技能树未解锁"提示，不阻塞存档 |
| 相位仪掉落/商店删除后玩家无法获得新相位仪 | 通用仪新游戏全解锁作初始，技能树节点作为主要获取途径 |

## 不做的事

- 不删强化①（纯纳米手动投入）—— 保留
- 不改战斗公式（enhance_mult 乘区保留）
- 不删改造系统（mods + 兵种专属改造保留）
- 不删军衔/稀有度（派生乘区保留）
- 不删符文之语系统（保留）
- 不改敌方系统（enemy_phase_masters/敌方加成链不动）
