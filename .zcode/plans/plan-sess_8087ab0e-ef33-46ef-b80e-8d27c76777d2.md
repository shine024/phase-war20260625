# 敌方相位师情报面板对齐我方（两路径统一）

## 目标
让敌方相位师在情报面板的信息完整度对齐我方，并消除敌方"基地路径"与"单位路径"两条路径的内部不一致。仅改 `scenes/ui/card_info_panel.gd`。

## 根因
`_show_enemy_phase_driver`（基地路径，1087-1139）相对我方 `_show_player_phase_driver`（1143-1211）缺：相位仪星级维度、符文槽位比+符文之语、主动能力、traits；且敌方内部"单位路径"（1397-1489）有 traits 而基地路径没有。

## 数据可得性（均已核实 API 存在）
| 待补信息 | API | 位置 |
|---|---|---|
| 相位师星名 | `evaluate(cfg)` 返回 `stars`/`star_name` | master_power_evaluator.gd:647 `_score_to_stars` |
| 符文之语 | `RunewordMatcher.check_active_runewords(ids, slot_count)` + `RunewordDefinitions.get_runeword_name(id)` | managers/runeword_matcher.gd:29, data/runewords.gd:1075 |
| 主动技能 | `EnemyPhaseMasters.get_master_active_spells(id)` → `[{name,description,cooldown}]` | enemy_phase_masters.gd:174 |
| 相位仪特殊效果 | `EnemyPhaseEquipment.get_phase_instrument(id).special_effects`(字符串ID数组) + `LeaderboardPresenter._translate_special_tag(tag)` | enemy_phase_equipment.gd:201, leaderboard_presenter.gd:469 |
| 相位仪稀有度 | `get_phase_instrument(id).rarity` | enemy_phase_instruments.json |
| 符文槽位上限 | `clampi(2 + level/10, 2, 4)`（与 `_derive_runes` max_count 一致） | enemy_phase_masters.gd:255 |

## 改动点

### 改动1：重构 `_show_enemy_phase_driver`（基地路径，card_info_panel.gd:1087-1139）
保留敌方独有角色设定（档案名/势力/称号），按我方字段顺序补齐：
- **相位师等级行合并星名**：`相位师等级：Lv.N` → `相位师等级：Lv.N · N★ 星名`（与我方1177行一致）；总战力行相应去掉重复星名 → `总战力：N`（与我方1179行一致）
- **相位仪行加稀有度**：`相位仪：名` → `相位仪：名（稀有度中文）`。敌方无 star，用 rarity 映射中文（common→普通/uncommon→精良/rare→稀有/epic→史诗/legendary→传说/mythic→神话）对齐我方"★星级"维度
- **符文行升级**：`符文：列表` → `符文：N/槽位上限（符文之语：名/名）列表`。槽位上限=clampi(2+level/10,2,4)；符文之语查 RunewordMatcher+get_runeword_name
- **新增【主动能力】段**：master.active_spells 逐条 `◆ 名：描述（冷却N秒）` + 相位仪 special_effects 翻译后 join（用户选"两者都显示"）
- **新增【相位师特性】段**：从 cfg.traits 取，格式 `◆ 名：描述`（与单位路径1465-1466一致，消除内部不一致）

### 改动2：重构 `_show_enemy_phase_master_unit`（单位路径，card_info_panel.gd:1397-1489）
补齐与基地路径一致的缺失项：
- 符文行加槽位比+符文之语（同上格式）
- 相位仪行加稀有度
- 新增【主动能力】段（active_spells + special_effects，同基地路径）

### 改动3：新增3个辅助函数（card_info_panel.gd，与现有 `_format_enemy_runes`/`_get_enemy_instrument_display_name` 同位置 ~1052-1085）
- `_format_enemy_runes_full(runes, level)`：符文列表 + 槽位比 + 符文之语（复用 `_format_enemy_runes` + runeword 查询），两路径共用
- `_format_enemy_active_abilities(pm_id, inst_id)`：active_spells + special_effects 合并格式化，两路径共用
- `_enemy_instrument_rarity_zh(rarity)`：稀有度→中文，两路径共用

## 设计决策
1. **相位仪用稀有度而非编造星数**：敌方相位仪数据模型是 rarity 驱动（无 star 字段），强映射星数是编数据。显示稀有度中文名是最诚实的维度对齐。
2. **被动技能不显示**：用户只要求"主动能力两者都显示"；我方无被动技能概念，补被动会破坏对齐。保持不显示。
3. **槽位上限用派生公式**：敌方无真实槽位数据，用 `_derive_runes` 同款 `clampi(2+level/10,2,4)` 作分母，反映"派生时就按此上限选符文"的语义。
4. **辅助函数提取共用**：两路径的符文/主动能力/稀有度格式化逻辑相同，提取3个辅助函数避免重复，保证两路径字面一致。
5. **special_effects 调用 LeaderboardPresenter 翻译**：复用已注册 class_name 的 static 方法，不重复维护56条翻译表。下划线前缀 static 在 GDScript 可跨类调用。

## 不改的东西
- 我方 `_show_player_phase_driver` 完全不动（我方是基准）
- 敌方独有角色设定（档案名/势力/称号/原始level）保留
- 数据文件（enemy_phase_masters.json / enemy_phase_instruments.json / .gd）不动——数据已就绪，纯展示层改动
- 被动技能不显示（无对应需求）
