# UI 全面审查修复计划

基于对 65+ 个 UI 面板脚本/场景的系统审查，修复发现的 **5 个 CRITICAL + 7 个 HIGH + 6 个 MEDIUM** 问题。按用户决策：全部修复；排行榜改用真实玩家进度；拆解卡牌 + 删除存档槽加确认弹窗。

---

## 阶段 A：CRITICAL — 数据真实性 + 破坏性操作保护

### A1. 排行榜「相位师排名」改用真实玩家进度生成（去假数据）
**问题**：`leaderboard_panel.gd:177-185` 硬编码 7 个虚构 NPC（终焉之镰/炽焰星痕…）名字/胜场/胜率 + `_simulate_faction_battles()` RNG 模拟战斗 + 标签页标题自带"(预热)"，两处重复（`leaderboard_data.gd:42-53`）。

**修复**：用真实游戏进度派生排行榜数据：
- 玩家行：从 `LevelProgressManager.get_max_unlocked_level()` / `get_level_stars()` / `get_era_progress()` 读真实进度
- 各势力行：从 `FactionSystemManager.get_territory_count(fid)` / `get_controlled_levels(fid)` 读真实占领数
- 对比基准行：基于玩家进度派生若干"虚拟对手"（用势力占领数为锚点的温和浮动，不再写死名字/胜率，而是用"第N位挑战者"+进度比例）
- 移除 `_simulate_faction_battles()` 假战斗，改为直接读实时数据
- 标签页标题 "(预热)" → 去掉
- **文件**：`leaderboard_panel.gd`（主改）、`leaderboard_data.gd`（同步去假数据/模拟）

### A2. 删除存档槽加确认弹窗
**问题**：`save_slot_manager.gd:160` `_on_delete_slot()` 一键执行 `SaveManager.delete_slot()`，不可逆数据丢失无确认。

**修复**：复用 `card_enhancement_panel` 的 `ConfirmationDialog` 模式（.tscn 加节点 + .gd 连 `confirmed` 信号）。在 `_on_delete_slot` 先弹窗，确认后才执行删除。
- **文件**：`save_slot_manager.gd` + `save_slot_manager.tscn`（如存在；否则代码动态建弹窗）

### A3. 拆解卡牌加确认弹窗
**问题**：`backpack_presenter.gd:239` `on_dismantle_button_pressed()` 一键拆解（消耗卡换研究点+纳米），无确认。

**修复**：在拆解执行前弹 `ConfirmationDialog`（显示将获得的资源预览），确认后才执行。弹窗在 `backpack_panel.gd`（view 层）或 presenter 层按现有架构落点。
- **文件**：`backpack_presenter.gd` / `backpack_panel.gd`

### A4. 排行榜敌方相位师详情：重复防御行 bug
**问题**：`leaderboard_presenter.gd:434` 和 `:436` 两行都是 `if pstats.has("defense")` → "防御:NN" 显示两次（第二行应为移动速度）。

**修复**：第二行改为读 `move_speed`（若存在），或删除重复行。
- **文件**：`leaderboard_presenter.gd`

### A5. 词缀 tooltip 死代码 match 分支
**问题**：`card_affix_tooltip.gd:231-234` 三个相同 `GC.CardType.COMBAT_UNIT` case，只有第一个（蓝色）生效，橙色/紫色战斗单位分支是死代码。

**修复**：调查 CombatKind（轻装/装甲/空军/炮兵/工兵）后按实际战斗子类型着色；若数据不可得则删除死分支保留单一颜色。
- **文件**：`card_affix_tooltip.gd`

## 阶段 B：HIGH — 可读性 + 布局 + 反馈

### B1. growth_panel 居中修复 + DetailCol 加滚动
**问题**：`growth_panel.tscn:262-265` 垂直偏移不对称（top -340 / bottom 320，整体下移 10px，非真正居中）；右侧 DetailCol（DetailHeader+GridBody+DetailFooter）直接堆叠在固定 660px 面板内，内容多时被挤/裁剪，无 ScrollContainer（兄弟面板 card_enhancement/modification 都有）。

**修复**：
- 偏移对称化：top/bottom 改为 -330/+330（真正居中）
- 在 DetailCol 的 VBoxContainer 外包一层 ScrollContainer（或把 DetailCol 内容移入新建 ScrollContainer），因为代码用 `%NodeName`（unique_name_in_owner）取节点，路径无关父结构，改 .tscn 结构不破坏代码引用
- **文件**：`growth_panel.tscn`（结构微调，代码零改）

### B2. 装备法则槽浅色背景上的浅色文字对比度修复
**问题**：`equipped_passives_box.gd:88-91` 法则槽用浅黄(`0.9,0.85,0.55`)/浅蓝(`0.55,0.7,0.9`)背景，但 Label 未设 font_color → 继承全局近白色，浅底白字难读。

**修复**：在 Label 上设深色 font_color（浅黄底用 `Color(0.15,0.12,0.05)`，浅蓝底用 `Color(0.05,0.1,0.2)`）。
- **文件**：`equipped_passives_box.gd`

### B3. 背包卡牌项 7-8px 字体放大到可读
**问题**：`backpack_card_item.gd:581`（底部信息行 font_size=8）、`:902`（名字 clamp 最小 7px）、`:887`（军衔 clamp 最小 8px）、`backpack_card_item.tscn:91`（font_size=9）。

**修复**：最小值统一提到 11（与 DesignTokens.FONT_SIZE_SMALL 对齐）；底部信息行 8→11。
- **文件**：`backpack_card_item.gd` + `backpack_card_item.tscn`

### B4. 存档/导入/导出失败对玩家可见（不再静默）
**问题**：`save_slot_manager.gd:157/192/199/220` 失败只 `push_error`，玩家看不到；兄弟 `global_save_button.gd` 已有 `_show_notification("❌ 存档失败")` 正确做法。

**修复**：在 save_slot_manager 的各失败分支补玩家可见反馈（复用 toast 或内联错误标签，与 global_save_button 对齐风格）。
- **文件**：`save_slot_manager.gd`

### B5. 排行榜敌方相位师装备 raw 英文标签翻译
**问题**：`leaderboard_presenter.gd:441` `tags_lbl.text = "  ".join(pspecial)` 把 raw 英文 effect tag（steel_skin_basic/burning_aura_advanced…）直接显示给中文玩家。

**修复**：加一个 `_translate_special_tag()` 翻译表（复用 card_info_panel 的改造 key 翻译模式），把 raw tag 转中文。

### B6. 合成失败原因 fallback "unknown" → 友好中文
**问题**：`synthesis_panel.gd:396` 失败提示 fallback 到字面量 `"unknown"`。

**修复**：fallback 改为 `"未知错误，请稍后重试"` 或类似友好文案。

### B7. 词缀 tooltip 动态宽度无上限 + 效果文本无 autowrap

## 不做的事（明确排除）
- **商店/合成/改造加确认弹窗**：用户未选（仅选拆解+删存档），这些操作频率高/资源量小，保持一键执行避免繁琐
- **3秒 await 加载指示器**：经核实 reinforcement/modification/evolution 的 3s await 是成功消息自动隐藏计时，非操作中等待，无需改
- **各长列表加排序/过滤**：工作量超出本轮范围（需新建排序 UI 组件），backpack 已有完整 filter/sort 可作后续模板
- **raw card_id 显示中文化**：涉及 65+ 面板的统一 display_name 取值，属独立大任务
- **"未知" fallback 统一**：~25 处分布广，属防御性编程现状，本轮只修确认的 bug 性 fallback
