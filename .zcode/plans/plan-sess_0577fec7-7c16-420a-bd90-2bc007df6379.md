## 修复：换装时背包多出新卡

### 根因
`equip_card`（`phase_instrument_manager.gd:680-685`）换装分支把"换装"拆成两个独立信号，且顺序倒置：
1. 先 `card_added_to_backpack.emit(old_card)` → 旧卡入包（中间态背包同时含新旧两卡）
2. 后 `card_equipped.emit(new_id)` → 新卡出包

叠加 `backpack_data.remove_card`（backpack_data.gd:157-161）**找不到时静默返回 `true`**，当多监听者时序竞态导致 `remove_card(new_id)` 落空时，新卡未被移除却报告成功 → 槽位有新卡 + 背包也有新卡 = 重复。这就是"有时多出要装备进相位仪中的卡"。

### 策略：两者都做（card_swapped 原子信号为主，remove_card 防御为辅）

`card_swapped` 的订阅者回调内部按"先移新卡再加旧卡"执行——这**本身就等价于信号顺序调换 + 原子化**，两者统一为一个机制。

### 改动 1：新增 `card_swapped` 原子信号
**`scripts/signal_bus.gd`** — 在 `card_equipped` 附近新增：
```gdscript
## 换装原子信号：槽位原有 old_card 被替换为 new_card_id。
## 订阅者一次性完成"移新卡出包 + 加旧卡入包"，避免双信号中间态导致背包重复。
## 仅 equip_card 的"替换已有卡"分支 emit；装到空槽仍走 card_equipped，unequip 仍走 card_added_to_backpack。

```

### 改动 4：presenter 新增 _on_card_swapped 回调
**`scenes/ui/backpack/backpack_presenter.gd`**：
- `_connect_global_signals`（L84-91）新增 connect `card_swapped` → `_on_card_swapped`
- `_disconnect_global_signals` 对应 disconnect
- 新增回调（关键：**先移新卡，此时 _data 里一定有它**；再加旧卡）：
```gdscript
func _on_card_swapped(_slot_index: int, old_card: CardResource, new_card_id: String) -> void:
    if _data == null:
        return
    # 1. 先移新卡出包（换装瞬间新卡必在 _data 中，remove 必成功）
    var removed: bool = _data.remove_card(new_card_id, true)
    if not removed:
        push_warning("[BackpackPresenter] card_swapped: 新卡 %s 未在背包中找到（可能时序异常）" % new_card_id)
    # 2. 再加旧卡入包
    if old_card != null:
        var old_id: String = old_card.instance_id if not old_card.instance_id.is_empty() else old_card.card_id
        if SaveManager and SaveManager.has_method("consume_pending_backpack_card_id"):
            SaveManager.consume_pending_backpack_card_id(old_id)
        _data.add_extra_card(old_id, true)
    if not _is_view_visible():
        _grid_dirty_while_hidden = true
    else:
        _refresh_card_grid()
```

### 改动 7：remove_card 不再静默成功（防御性）
**`scenes/ui/backpack/backpack_data.gd:147-161`** — 找不到时返回 `false`（保留 `cards_changed.emit()` 让 UI 仍刷新）：
```gdscript
func remove_card(card_id: String, silent: bool = false) -> bool:
    if card_id.is_empty():
        return false
    var idx: int = _extra_card_ids.find(card_id)
    if idx >= 0:
        _extra_card_ids.remove_at(idx)
        _invalidate_cards_cache()
        if not silent:
            cards_changed.emit()
        return true
    # 不在额外卡中：返回 false 让调用方感知失败（原静默返回 true 会掩盖时序 bug）
    _invalidate_cards_cache()
    if not silent:
        cards_changed.emit()
    return false
```
**调用方安全核对**：`presenter._on_card_equipped:182` 用 `removed` 控制增量路径，false 时跳过增量直接全量刷新（行为不变）；`backpack_panel._fallback_on_card_equipped:259` 忽略返回值（不受影响）；新增 `_on_card_swapped` 检查返回值并 push_warning。

---

### 关键设计决策
1. **card_swapped 只覆盖换装分支**——装到空槽仍走 `card_equipped`，unequip 仍走 `card_added_to_backpack`，买卡/掉落/制造路径零变化。最小侵入，向后兼容。
2. **回调内部"先移后加"顺序**等价于信号顺序调换——新卡在"刚从背包拖出"的最确定时刻被移除，消除竞态窗口。这是"两者都做"的统一实现。
3. **loadout_sync 同步改造**——虽是死代码，保持一致防将来激活时重现 bug。
4. **remove_card 返回 false 是防御层**——即使 card_swapped 逻辑有疏漏，调用方能感知并告警，不再静默吞错。
5. **强化 AGENTS.md 铁律**——card_swapped 让"槽位卡与背包卡互斥"在信号层得到原子保证，符合核心架构"单一事实来源"原则。

### 验证
1. **Godot headless --check-only**：验证 7 处改动语法正确（项目体量 5 分钟超时属既有现象，能构建到 133 卡即算通过）。
2. **Grep 静态核对**：`card_swapped` 在 signal_bus 定义 + 2 处 emit（主文件+loadout_sync）+ 3 处 connect（presenter/save_manager/panel）+ 3 处回调定义，全链路拼写一致。
3. **状态推演**：手动验证换装时间线——初始背包 `[新卡A]` 槽位=旧卡B → card_swapped → 先 remove(A) 成功 → 再 add(B) → 终态背包 `[旧卡B]` 槽位=A，无中间态重复。对比买卡/unequip 路径不受影响。
