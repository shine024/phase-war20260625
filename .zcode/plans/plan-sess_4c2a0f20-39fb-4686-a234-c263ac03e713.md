# 修复方案：敌人 HP 同步 bug + 文档同步

## 问题根因（已确认）

`enemy_unit.gd` 持有两套属性数据：
- **裸字段**（`hp`/`max_hp`/`attack_damage`/`defense`）— `take_damage` 扣血、`_update_hp_bar` 血条、死亡判定读这些
- **`stats: UnitStats` 对象** — AttackCalculator 三维攻击结算、hp_regen 上限读这些

`_apply_archetype_stats` 和 `_apply_ng_plus_scaling` 都**同步修改**两套；但下面**两个 spawn 后加成函数只改 stats，不同步裸字段**，导致：
- 血条/扣血用未加成值，单位实际比面板脆 30%（tier）或更多（phase master）
- hp_regen 上限却按加成后的 stats.max_hp，造成"面板显示 HP 高 / 实际脆"的不一致
- 只有当 elite 词缀恰好 roll 到 `max_hp` 时，`apply_elite_affixes` 的 L450-453 才把 stats 同步到裸字段（此时 tier/phase_master 加成一并"意外生效"），这就是用户看到"实际 HP 比理论值高/低飘忽不定"的根因

## 修复点

### 修复1：`scenes/units/enemy_unit.gd` — 新增 `_sync_bare_fields_from_stats()` 辅助方法

新增一个方法，把 stats 的关键数值字段同步到裸字段：
```gdscript
func _sync_bare_fields_from_stats() -> void:
    if stats == null:
        return
    # HP：保持当前 hp/max_hp 比率，把 stats.max_hp 的加成传导到裸字段
    var ratio: float = clampf(hp / maxf(1.0, max_hp), 0.0, 1.0) if max_hp > 0.0 else 1.0
    max_hp = maxf(1.0, float(stats.max_hp))
    hp = maxf(1.0, max_hp * ratio)
    # 攻击：stats.attack_damage 是 attack_light 别名（与裸 attack_damage 语义一致）
    attack_damage = maxf(0.1, float(stats.attack_damage))
    # 防御：stats.defense 是格子战单一值
    if "defense" in stats:
        defense = maxf(0.0, float(stats.defense))
    _update_hp_bar()
```
（保持 HP 比率是关键——避免满血单位加成后突然不满血）

### 修复2：`managers/battle/battle_spawn_system.gd:1009-1010` — `_apply_enemy_loadout_tier_if_normal_battle` 末尾调同步

把原来只调 `_update_hp_bar()` 改为调 `_sync_bare_fields_from_stats()`（若单位有此方法）：
```gdscript
# 旧：if unit.has_method("_update_hp_bar"): unit._update_hp_bar()
# 新：
if unit.has_method("_sync_bare_fields_from_stats"):
    unit._sync_bare_fields_from_stats()
elif unit.has_method("_update_hp_bar"):
    unit._update_hp_bar()
```

### 修复3：`managers/battle/battle_spawn_system.gd:1034-1036` — `_apply_enemy_phase_master_bonus_if_active` 末尾同样改

原注释说"同步单位节点的派生字段（hp/max_hp 等），让 UI 血条与 stats 一致"，但代码只调 `_update_hp_bar()`，是空同步。改为调 `_sync_bare_fields_from_stats()`。

### 修复4：`scenes/units/enemy_unit.gd:444-453` — `apply_elite_affixes` 简化

原代码在 `has_hp_affix` 块内才同步裸字段（条件性同步），现在有了统一的 `_sync_bare_fields_from_stats()`，改为无条件调用——无论 roll 到哪个词缀，都把 stats 同步到裸字段。attack_damage 词缀（frenzy +30%）现在也保证同步生效。

### 修复5：AGENTS.md — 更新过时的 9 维公式记录

在 v7.x 相位师战力相关章节（L966-1088）追加一段说明：9 维加权公式已被代码废弃，当前 `evaluate()` 实际是 3 分量直接相加（A相位仪 + F载卡 + H符文），其他维度函数为死代码。STAR_TIERS 阈值实际是 `0/800/1600/3200/6000/9500/20000`。避免后续协作者被文档误导。

## 影响面分析（行为变化）

- **普通关敌兵**：tier 加成真正生效，HP 比修复前高 10-30%（取决于时代进度选档），用户反馈的"HP 比理论值高"现在变成**稳定可预测**的数值，而非飘忽
- **相位师战产兵**：phase_master 加成同步生效，产兵 HP/攻击与面板一致
- **精英怪**：所有词缀（不只 max_hp）都触发裸字段同步，attack_damage/frenzy 等词缀的攻击力加成现在真正影响战斗（之前只改 stats 三维攻击，裸 attack_damage 不变，但 _do_attack 走 stats 路径所以攻击其实已生效——这次主要保证面板显示一致）
- **蜂群（swarm_enemy_slot）**：不受影响（不走 `_create_enemy_unit_with_id`）
- **向后兼容**：新方法是纯增量，没有改老字段语义；旧存档/旧单位行为不变
