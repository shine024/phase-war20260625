# 修复我方战斗卡卡图映射（74张回退卡接入专属图）

## 问题根因

112 张我方战斗卡中，**74 张（66%）显示成错误的通用图**：

- 代码 `card_icon_path_for()`（ui_asset_loader.gd:245）取图链路：`foe_<我方card_id>` → manifest 查 → 查不到则走 ERA_KIND 通用回退
- 我方卡 ID 和敌方卡 ID 是**两套命名体系**（如我方 `ww2_panther` vs 敌方 `ww2_arm_panther_e`），manifest 只认敌方命名
- 结果 74 张卡全部落到 ERA_KIND 回退：7 种二战坦克全显示成谢尔曼、11 张现代步兵全显示成皮卡武装、冷战 7 种坦克全显示成 T-55……
- 翻转操作本身正确（已验证），enemy 原图也已整理好，问题纯粹在**取图映射**

## 修复方案

在 `card_icon_path_for()` 的 manifest 查询失败后、ERA_KIND 回退前，**插入一张"我方 card_id → vis_player 编号"的 override 映射表**，让这 74 张卡拿到各自语义最匹配的专属图。

### 改动文件（仅 1 个）

**`scripts/ui_asset_loader.gd`**：
1. 新增常量字典 `PLAYER_ICON_OVERRIDE`（74 条：我方 card_id → vis_player_NNN）
2. 在 `card_icon_path_for()` 第 1 步（manifest 查询）和第 2 步（archetype）之间，插入 override 查询：若该 card_id 在 override 表中，直接返回 `player/<vis_player_NNN>.png`

### 为什么这样改（而非改 manifest 或改 card_id）

| 方案 | 评估 |
|------|------|
| **A. ui_asset_loader 加 override 表（本方案）** | ✅ 改 1 个文件、74 条字典、5 行查询逻辑；不动 manifest/不改 card_id（避免影响敌方/存档/掉落链路）；向后兼容（仅对当前走回退的 74 张生效，38 张已命中的不受影响） |
| B. 改 manifest 把我方 ID 加进去 | ❌ manifest 是敌方数据核心，被我方/敌方/掉落/缴获共用，改动面大、风险高 |
| C. 改我方 card_id 对齐敌方命名 | ❌ card_id 是存档 key，改名会破坏所有现有存档（违反 InstanceRegistry 养成隔离铁律） |

### 不受影响的部分

- 已 manifest 命中的 38 张卡：行为不变
- ERA_KIND_FALLBACK_ICON / SHAPE_KEY_UNIT_ICON：保留（作为 override 也未命中时的最终兜底）
- 敌方战场单位取图：不受影响（走 `for_player=false` → vis_enemy）
- 存档/养成/掉落：完全不受影响（只改 UI 取图）
