# 弹道与击中效果系统补强方案

## 调查结论（关键架构发现）

经深入核对，项目弹道系统**本身已高度完善**（12 档武器完整分流弹道/外观/拖尾/音效/命中配方）。本次四个任务中，有三个的真实情况与最初假设不同：

| 任务 | 最初假设 | 实际真相 |
|------|---------|---------|
| 轻武器命中特效 | 被跳过，需删守卫 | **SMG/PISTOL 走直射 batch，batch 命中已在调特效，本来就有**；`bullet.gd:423` 跳过列表是死代码（这些武器根本不走 bullet）。需要的是**优化配方使更明显** |
| 命中特效贴图化 | 全无贴图基建 | **56 个命中贴图 + 查找逻辑全在仓库，只是接线断开**（`impact_texture_by_name` 从未被调）。只差在工厂加判断 |
| 改造专属视觉 | 改 bullet 即可 | **子母弹/温压/制导全是曲射，走 batch 不走 bullet**。必须改 `simple_indirect_projectile_batch.gd` 的 fire 签名 + _proj 字典 + 命中点 |
| 清理遗留系统 | 删文件即可 | battle_effects_system 死代码可删；visual_effects_manager 有 2 处 create_explosion 调用需先迁移 |

## 四阶段实施

### 阶段 1：命中特效贴图化（重型爆炸武器）

**目标**：给 ROCKET(3)/FLAK(7)/MISSILE(9) 等重型爆炸武器的命中接上现有 56 个贴图，让爆炸有"形状感"。

**改动文件**：
- `scripts/weapon_projectile_vfx.gd`（接线核心）
  - `spawn_impact_with_kind`（:331）签名增加 `weapon_name: String = ""` 参数（透传给贴图查找）
  - 内部逻辑：若 `weapon_name` 非空且 `impact_texture_by_name(weapon_name)` 有值 → 新增 `_spawn_impact_with_texture(...)`（Sprite2D + 贴图 + 缩放淡出 tween），否则 → 现 `VfxImpactFactory.spawn_layered_impact` 粒子路径
  - 新增 `_impact_sprite_pool: Array`（Sprite2D 池）+ `_acquire_impact_sprite` / `_release_impact_sprite`（参考现有池模式，上限 80）
- `scripts/battle/vfx_impact_factory.gd`
  - 新增 `_impact_sprite_pool: Array`（Sprite2D 池）+ `_acquire_impact_sprite` / `_release_impact_sprite`（参考 `_acquire_ring` :521 模式）
  - 新增 `spawn_impact_sprite(parent, pos, texture, scale, life)` public 方法
- `scenes/units/bullet.gd`（调用方补 weapon_name 透传）
  - `_spawn_impact_v2`（:460）和 `_spawn_impact_explosion`（:591）调 `spawn_impact_with_kind` 时补传 `_weapon_name`
- `managers/battle/simple_indirect_projectile_batch.gd`（batch 调用方）
  - `_spawn_impact_explosion`（:400）调 `spawn_impact_with_kind` 时补传 `weapon_name`（batch 的 `_proj` 字典需先存 weapon_name，见阶段 3）

**设计决策**：贴图优先于粒子（有贴图用贴图，无贴图回退粒子），保证零贴图武器行为不变。仅重型爆炸武器有贴图（符合"仅重型爆炸武器"决策），轻武器仍纯粒子。

### 阶段 2：清理遗留特效系统

**改动文件**：
- **删除** `scenes/effects/battle_effects_system.gd`（923 行死代码，0 调用方，未 autoload，无 .tscn 实例化）
- **删除** `scenes/effects/battle_audio_system.gd`（依赖它，同样 0 调用方）
- `managers/battle/phase_instrument_abilities.gd`（:9 preload / :244 调用 `VisualEffects.create_explosion`）→ 改为调 `VfxImpactFactory.spawn_shockwave(parent, pos, radius)`（功能等价：扩散环 + 粒子）
- `managers/battle/enemy_phase_instrument_abilities.gd`（:14 preload / :193 同上）→ 同样迁移
- **删除** `scenes/effects/visual_effects_manager.gd`（迁移完 2 处后，593 行里剩余 7 个方法全死）
- `scenes/units/bullet.gd`（:15）删除孤儿 `ARTILLERY_IMPACT_TEX` 常量声明（从未使用）
- `scripts/weapon_projectile_vfx.gd`（:40）`IMPACT_COLOR_BY_WT` 与 `vfx_impact_factory.gd`（:406）`COLOR_BY_WT` 去重——保留工厂版，weapon_projectile_vfx 改为引用工厂常量
- **保留** `scripts/card_grid_fx.gd`（兜底路径活跃，与主工厂互斥，属视觉变更不宜本次动）

### 阶段 3：武器类改造专属视觉（核心 5 个）

**目标**：让子母弹/温压弹/近炸引信/制导炮弹/炮射导弹在战场上有专属弹道与击中视觉。

**数据通道设计**（关键决策）：
- 改造 effects 字典加新 key `vfx_variant`（字符串，如 `"cluster"`/`"thermobaric"`/`"proximity"`/`"guided"`/`"gun_missile"`）
- `modification_registry.gd` `apply_to_weapon_slot`（:798）的 match 加分支：`"vfx_variant": result._mod_effects["vfx_variant"] = effect_value`（复用 WeaponResource 现有 `_mod_effects` 字段，:67，clone 时保留）

**改动文件**：
- `data/modification_modules/artillery_mods.gd` — 4 个改造 effects 加 `vfx_variant` key：
  - `art_04_cluster_munition`（子母弹）→ `"cluster"`
  - `art_11_thermobaric`（温压弹）→ `"thermobaric"`
  - `art_03_guided_shell`（制导炮弹）→ `"guided"`
  - `art_05_proximity_fuze`（近炸引信）→ `"proximity"`
- `data/modification_modules/armor_mods.gd` — `arm_07_gun_missile`（炮射导弹）→ `"gun_missile"`
- `scripts/systems/modification_registry.gd` — `apply_to_weapon_slot`（:798-802）加 `"vfx_variant":` 分支写入 `_mod_effects`
- `managers/battle/simple_indirect_projectile_batch.gd`（核心改动）：
  - `fire(...)`（:96）签名末尾加 `p_vfx_variant: String = ""` 参数
  - `_proj` 字典（:113-132）存 `vfx_variant` 字段
  - 命中点 `_spawn_impact_explosion`（:400）读 `r.get("vfx_variant","")` 透传给 `spawn_impact_with_kind` 的 opts
- `scripts/battle/construct_unit_ai.gd`（:442/446）和 `scenes/units/enemy_unit.gd`（:1165）— 调 indirect batch `fire(...)` 时从 `weapon_resource._mod_effects.get("vfx_variant","")` 读出并传入
- `scripts/weapon_projectile_vfx.gd` — `spawn_impact_with_kind` 的 opts 读 `vfx_variant`，按值走不同特效组合：
  - `"cluster"`：主爆炸 + 6 个小溅射点（子弹药撒布，调 `VfxImpactFactory.spawn_layered_impact` 在周围随机点位）
  - `"thermobaric"`：大冲击波（半径×1.5）+ 二次延迟爆炸（0.15s 后再 spawn 一层）
  - `"proximity"`：命中点上方空爆闪光（高空环 + 向下火花锥）
  - `"guided"`：命中前最后 0.2 弧段加尾迹光带（命中精准指示）
  - `"gun_missile"`：与普通导弹区分（更细弹体 + 蓝白尾焰，标识"炮射"而非标准导弹）
- `scripts/battle/vfx_impact_factory.gd` — 新增对应的 spawn 辅助方法（如 `spawn_cluster_burst` / `spawn_thermobaric_blast`），复用现有 ring/spark/debris 池

**设计决策**：变体标识走 `_mod_effects`（现成挂载点，clone 保留），不新建字段；命中特效差异集中在 `weapon_projectile_vfx.gd`（两条渲染路径的共同收口）一处生效，最小改动。

### 阶段 4：轻武器命中特效优化

**真相**：SMG/PISTOL 走直射 batch，batch 命中已在调特效。问题是配方偏弱（28 个小火花 + 36px 小环，在高速连发下视觉不明显）。

**改动文件**：
- `scripts/battle/vfx_impact_factory.gd` — `_impact_recipe`（:442-447）的 `0, 4:` 分支：
  - 火花数 28→16（单次更少，但**提高单粒子亮度** scale 1.5→2.5）
  - 环半径 36→28（更小更集中，像弹着点而非爆炸）
  - 颜色调整为更亮的黄白（与"轻武器弹着"语义匹配）
- `scenes/units/bullet.gd`（:419-423）— 清理 `_SKIP_IMPACT_WEAPON_TYPES` 死代码常量 + `_spawn_tex_impact_at`（:426-427）的跳过 return（因 SMG/PISTOL 不走 bullet，此分支实际不触发，但保留死代码会误导）。改为注释说明"轻武器走直射 batch，命中特效由 batch 处理"
- **节流确认**：直射 batch 的 `_apply_hit`（simple_player:163 / simple_enemy:160）调 `spawn_impact_with_kind` 时，工厂的 `_spark_pool`（MAX_SPARKS=200）硬上限节流已生效，MG 4次/秒×多单位最坏也只会有 200 火花上限，无性能风险

**设计决策**：不删除而是"重平衡配方"——降低单次粒子数（减负载）但提高单粒子亮度（增可见性），在高速连发场景下既不卡顿又能看到弹着反馈。

## 验证计划

- **Godot `--check-only`**：确认全部改动无语法错误（133 卡构建通过）
- **静态 Grep 核对**：
  - `vfx_variant` 链路（改造 effects → registry → batch fire → spawn_impact_with_kind opts）全拼写一致
  - `impact_texture_by_name` 接线后所有重型爆炸武器调用方都传了 weapon_name
  - 删除的文件无残留引用（battle_effects_system / visual_effects_manager / ARTILLERY_IMPACT_TEX）
- **运行时实机验证**（需游戏内）：
  - 装子母弹改造 → 对装甲目标开火 → 确认看到子弹药撒布多点爆炸
  - 装温压弹 → 确认看到二次爆炸
  - 重型导弹命中 → 确认显示贴图爆炸（而非纯粒子）
  - 冲锋枪连发 → 确认命中点有明显黄白弹着火花

- 不删 card_grid_fx.gd（兜底路径，属视觉变更，留待后续）
