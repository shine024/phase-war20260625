## 战斗胜利结算卡顿优化计划

### 现状分析

当前已有帧拆分（A→B→C→D），时序：
- **帧 A**：`end_battle` — 轻量清理
- **帧 B**：`_deferred_end_battle_finalize` — 掉落生成（**最重**）
- **帧 C**：`_deferred_end_battle_broadcast` — 任务通知 + `battle_ended.emit()` → 18个监听者
- **帧 D**：`show_battle_result` call_deferred — 结算面板UI

卡顿来源：
1. **帧 B**：`generate_battle_intel_harvest` 遍历 20-40 个击败敌人，每个 5 次掷骰 + 3 次 `ensure_loaded` 首次同步 `load()+new()+add_child()`
2. **帧 C**：`GameManager._on_battle_ended`（~170 行）同步完成全部奖励计算 + `_grant_phase_master_victory_reward`（Boss 战时额外 160 行）

### 优化方案：3 个改动点

#### 改动 1：战斗开始时预热 ManagerLazyLoader（消除首次 ensure_loaded 同步开销）

**文件**：`managers/battle/battle_manager.gd`
**位置**：`start_battle` 函数，`battle_started.emit()` 之前（约 L305）
**做法**：在战斗开始时调用 `ManagerLazyLoader.ensure_loaded()` 预热结算路径需要的所有 lazy manager。战斗通常持续数分钟，预热只花 1 帧，但消除了结算时首次 `load()+new()+add_child()` 的同步阻塞。

**预热列表**（对应帧 B/C 实际 ensure_loaded 调用）：
- `intel_discovery` — 帧 B 情报收获生成
- `quest` — 帧 C 任务通知 + 游戏管理器关卡进度
- `achievement` — 游戏管理器成就记录
- `level_progress` — 游戏管理器关卡进度更新
- `leaderboard` — 游戏管理器排行榜统计
- `story` — 游戏管理器必败战剧情（仅在必败战时需要，但无条件预热避免分支）
- `faction` — 游戏管理器势力反应
- `stat_boost` — 相位师奖励属性提升（仅 Boss 战，但预热开销极低）

**代码**：在 `SignalBus.battle_started.emit()` 前插入：
```gdscript
# v7.x 性能：预热结算路径需要的 lazy manager，消除结算时首次 ensure_loaded 同步开销
var _mll_pre = get_node_or_null("/root/ManagerLazyLoader")
if _mll_pre and _mll_pre.has_method("ensure_loaded"):
    for _pre_id in ["intel_discovery", "quest", "achievement", "level_progress",
                     "leaderboard", "story", "faction", "stat_boost"]:
        _mll_pre.ensure_loaded(_pre_id)
```

**影响**：消除帧 B 的 3 次首次实例化 + 帧 C 的 5+ 次首次实例化。后续 manager 已缓存，`ensure_loaded` 仅做 `is_instance_valid` 检查，约 0 开销。

#### 改动 2：帧 B 情报收获生成再拆一帧（把帧 B 负载减半）

**文件**：`managers/battle/battle_manager.gd`
**位置**：`_deferred_end_battle_finalize` 函数（L391-404）

**做法**：把情报收获生成从掉落表生成中拆到独立的一帧，形成 A→B→B'→C 四帧链：

- 帧 B：掉落表生成（DropManager.generate_battle_drops + 相位仪掉落）— 中等负载
- 帧 B'：情报收获生成（generate_battle_intel_harvest）— 原帧 B 最重部分
- 帧 C：不变

**具体改动**：在 `_deferred_end_battle_finalize` 中，掉落生成完成后不直接链到 `_deferred_end_battle_broadcast`，而是先链到一个新的 `_deferred_end_battle_intel_harvest` 函数：

```gdscript
func _deferred_end_battle_finalize(player_won: bool) -> void:
    # ①掉落表生成（中等负载）
    if player_won:
        _damage_system.try_grant_battle_affixes(phase_instrument)
        _battle_result = _damage_system.generate_battle_drops_only(
            true, _battle_elapsed_time,
            _spawn_system.get_enemy_wave_total(),
            _spawn_system.get_enemy_wave_interval(),
            _spawn_system.get_max_player_units_deployed(),
            _spawn_system.get_player_units_lost()
        )
    # 掉落表完成后，把情报收获延到下一帧
    call_deferred("_deferred_end_battle_intel_harvest", player_won)

func _deferred_end_battle_intel_harvest(player_won: bool) -> void:
    # ①b 情报收获生成（原帧 B 最重部分，现独立一帧）
    if player_won:
        _battle_result = _damage_system.generate_intel_harvest(_battle_result)
    # ②③④ 推迟到下一帧
    call_deferred("_deferred_end_battle_broadcast", player_won)
```

**配套改动**：`managers/battle/battle_damage_system.gd` 的 `generate_battle_completion_drops` 拆成两个函数：
- `generate_battle_drops_only(...)` — 只做掉落表生成 + 相位仪掉落（不含情报）
- `generate_intel_harvest(existing_result: Dictionary)` — 只做情报收获，接收已有的 `_battle_result` 字典，追加 `intel_harvest`/`eom_fragments` 字段后返回

**时序安全**：两帧都写 `_battle_result`——帧 B 写掉落/星级/时代，帧 B' 追加情报字段。`_is_phase_master_battle` 在帧 B' 仍可安全读取（帧 C 才清零）。

#### 改动 3：游戏管理器 `_on_battle_ended` 重负载延迟到结算面板之后

**文件**：`managers/game_manager.gd`
**位置**：`_on_battle_ended` 函数（L467-630）

**做法**：将 `_on_battle_ended` 拆成同步核心（状态切换 + reward_summary 组装）和延迟后处理（排行榜、碎片计算、势力反应、相位师奖励）。结算面板能在帧 C+1 构建出 UI，让玩家看到胜利画面和面板；延迟后处理在面板显示后执行，不影响玩家感知。

**拆分方案**：

同步部分（帧 C，~30 行）：
- `current_phase = POST_BATTLE`（必须同步）
- 必败战剧情标记（必须同步）
- 提取 battle_result + victory_stars
- **关键改动**：把 `show_battle_result` 从 call_deferred 改为立即准备 reward_summary 骨架，让面板显示不依赖延迟计算
- `_is_phase_master_battle` 标志暂存不清除（延迟部分需要）

延迟部分（帧 C+1，通过 call_deferred 执行）：
- `_grant_phase_master_victory_reward`（Boss 战奖励，~160 行）
- `_grant_basic_resources_for_current_level` + XP + 势力反应
- 关卡进度更新（LevelProgressManager + AchievementManager）
- 排行榜统计（3 次 update_*）
- 碎片/知识增量计算（`_calculate_blueprint_fragment_gain` / `_calculate_knowledge_gain`）
- `last_battle_reward_summary` 完整组装
- `_is_phase_master_battle` 清除

**具体实现**：

```gdscript
func _on_battle_ended(player_won: bool) -> void:
    current_phase = GamePhase.POST_BATTLE
    
    # 必败战剧情标记（同步）
    _handle_force_defeat_story()
    clear_final_battle_state()
    
    # 提取战斗结果（同步）
    var victory_stars: int = 0
    var era: int = 0
    var phase_instrument_drop: Dictionary = {}
    var intel_harvest: Dictionary = {}
    if BattleManager.has_method("get_battle_result"):
        var result = BattleManager.get_battle_result()
        victory_stars = int(result.get("victory_stars", 0))
        era = int(result.get("era", 0))
        phase_instrument_drop = result.get("phase_instrument_drop", {})
        intel_harvest = result.get("intel_harvest", {})
    
    # 记录战斗前资源（同步，延迟部分需要）
    _pre_battle_resources = {
        "nano": BasicResourceManager.get_total(BasicResources.ID_NANO_MATERIALS),
        "energy": BasicResourceManager.get_total(BasicResources.ID_ENERGY_BLOCK),
        "bp_nano": BlueprintManager.get_nano_materials()
    }
    
    # AFK 模式：同步处理（不走延迟，不弹面板）
    if _is_afk_running():
        # ... AFK 逻辑不变 ...
        call_deferred("_deferred_post_battle_rewards", player_won, victory_stars, era,
                      phase_instrument_drop, intel_harvest)
        return
    
    # 正常模式：立即弹结算面板 + 延迟计算奖励
    if main_scene and main_scene.has_method("show_battle_result"):
        main_scene.call_deferred("show_battle_result", player_won)
    # ... fallback ...
    
    # 延迟执行重负载奖励计算
    call_deferred("_deferred_post_battle_rewards", player_won, victory_stars, era,
                  phase_instrument_drop, intel_harvest)

func _deferred_post_battle_rewards(player_won, victory_stars, era,
        phase_instrument_drop, intel_harvest) -> void:
    # 相位师奖励
    if _is_phase_master_battle and not _current_phase_master.is_empty() and player_won:
        _grant_phase_master_victory_reward(_current_phase_master.get("name", "相位师"))
    _is_phase_master_battle = false
    _current_phase_master = {}
    
    # 基础资源 + XP + 势力反应
    if player_won:
        _grant_basic_resources_for_current_level()
        _grant_phase_field_xp_for_victory()
        _apply_faction_reaction_for_conquest()
    
    # 关卡进度 + 排行榜
    # ... 碎片/知识计算 ...
    # reward_summary 完整组装
```

**时序安全**：
- `_current_phase_master` 在延迟函数中才清除，延迟函数在 `battle_ended.emit()` 的 call_deferred 链上，此时 `_deferred_end_battle_broadcast` 已清零帧 C 的 `_phase_master_config`——但 `_current_phase_master` 在 GameManager 上，不受 BattleManager 影响，安全
- 奖励计算顺序：Boss 掉落→基础资源→关卡进度，延迟执行不改变相对顺序

### 优化前后对比

| 帧 | 优化前 | 优化后 |
|----|--------|--------|
| A | 清理（轻） | 清理（轻）+ **预热 manager** |
| B | 掉落生成 + 情报收获（**重**） | 掉落表生成（中） |
| B' | — | 情报收获（**重**，独立一帧） |
| C | 任务通知 + **18个监听者同步（含 GameManager 全部计算）** | 任务通知 + 18个监听者同步（**GameManager 仅状态切换+弹面板**） |
| C+1 | 结算面板UI | 结算面板UI + **延迟奖励计算** |

### 涉及文件

| 文件 | 改动类型 |
|------|---------|
| `managers/battle/battle_manager.gd` | 改动 1（start_battle 预热）+ 改动 2（拆帧 B'） |
| `managers/battle/battle_damage_system.gd` | 改动 2（拆 generate_battle_completion_drops 为两函数） |
