## 相位师显示改造：去掉派生等级 Lv，聚焦「名称 + 军团战力」

### 背景与现状

当前相位师面板显示三行重复信息：
```
相位师等级：Lv.9 · 4★ 大师   ← Lv.9 由 total_score 做 log10 映射派生（compute_display_level）
总战力：5124                  ← 与上面 Lv.9 是同一信息的两种表达，冗余
```

派生 Lv 本质就是把战力换算成等级数字，与「总战力」是同义重复。用户要求：去掉派生 Lv，把「总战力」改名为「军团战力」，名称维持现状。

### 改动范围（全局清理派生 Lv，但保留底层函数/信号可逆）

**决策：仅改 UI 显示层，保留 `compute_display_level`/`_raw_to_display_level` 函数定义和信号 `display_level` 参数不动。** 理由：①派生 Lv 的 log10 映射逻辑无 bug，只是 UI 不再需要展示；②保留函数让现有测试继续通过（避免改 3 个测试文件）；③保留信号参数避免改 emit/connect 全链路（4 处）。这是显示层改造，不动计算逻辑，风险最低、完全可逆。

### 不动的部分（底层保留）

- **保留** `EnemyPhaseMasters.compute_display_level` / `get_display_level_by_id` 函数定义（测试仍依赖，无 UI 调用即可）
- **保留** `MasterPlayerAssembler._raw_to_display_level` / `get_player_display_level` / `get_player_display_text` 函数定义（`get_player_display_text` 被 L1124 调用，需改为返回不含 Lv 的文本——见下方说明）
- **保留** `display_level` 字段在 evaluator 返回结构里（`evaluate_player_stars` 仍计算并存，UI 不读）
- **保留** 信号 `player_phase_master_power_changed` 的 `display_level` 参数定义（emit 处继续传，回调 `_level` 仍用下划线忽略）
- **保留** 所有测试文件（继续测 compute_display_level，函数还在所以照常通过）

### `get_player_display_text` 调整说明

`master_player_assembler.gd` L240-246 的 `get_player_display_text` 当前返回 `"Lv.%d %d★ %s"`。它被 `bottom_instrument_bar.gd` L1124 调用（非战斗场景兜底）。改返回 `"军团战力%d · %d★ %s"`（加 total_score 参数读取）。但该函数当前签名只传 pm，内部调 evaluate_player_stars 已能拿到 raw_total_score，可自取。
