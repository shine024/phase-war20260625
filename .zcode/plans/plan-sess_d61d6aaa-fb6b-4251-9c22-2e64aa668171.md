## 修复方案：产兵路径读取 UCT 三维攻击字段

### 根因
`_build_stats_from_archetype`（enemy_phase_field_driver.gd:937-941）无条件读旧字段 `cfg.attack_damage` 并按 0.8/0.7 比例派生三维，完全无视 cfg 里已被 UCT 覆盖的真实三维字段（attack_light/attack_armor/attack_air）。

`EnemyArchetypes.get_config` 在 v8.1 已用 UCT 数据覆盖了三维攻击字段（enemy_archetypes.gd:390-394），但 `_build_stats_from_archetype` 没读这些字段，所以覆盖对产兵路径无效。

### 对比验证
- ✅ `resolve_classic_enemy`（普通敌人路径，enemy_stat_resolver.gd:213-216）：已优先读三维字段，正确拿到 UCT 数据
- ❌ `_build_stats_from_archetype`（产兵路径，enemy_phase_field_driver.gd:937-941）：只读 attack_damage，无视三维

### 修复
让 `_build_stats_from_archetype` 复用 `resolve_classic_enemy` 的同款三维读取逻辑：

```gdscript
# 旧（L937-941）：
var dmg: float = float(cfg.get("attack_damage", 10.0))
c.attack_light = dmg
c.attack_armor = dmg * 0.8
c.attack_air = dmg * 0.7

# 新：优先读三维字段（UCT 已覆盖），无则回退 attack_damage + combat_kind 派生
if cfg.has("attack_light") or cfg.has("attack_armor") or cfg.has("attack_air"):
    c.attack_light = float(cfg.get("attack_light", 0.0))
    c.attack_armor = float(cfg.get("attack_armor", 0.0))
    c.attack_air = float(cfg.get("attack_air", 0.0))
else:
    var dmg: float = float(cfg.get("attack_damage", 10.0))
    c.attack_light = dmg
    c.attack_armor = dmg * 0.8
    c.attack_air = dmg * 0.7
```

### 同步修复：三维攻速
旧代码 L935 只读单一 `attack_interval`，但 UCT 覆盖提供了三维独立 interval（attack_light_interval/attack_armor_interval/attack_air_interval）。同步补上：

```gdscript
# 三维攻速（UCT 覆盖提供，无则回退单一 interval）
var ivl_l: float = float(cfg.get("attack_light_interval", interval))
var ivl_a: float = float(cfg.get("attack_armor_interval", interval))
var ivl_air: float = float(cfg.get("attack_air_interval", interval))
c.attack_light_speed = 1.0 / maxf(0.001, ivl_l)
c.attack_armor_speed = 1.0 / maxf(0.001, ivl_a)
c.attack_air_speed = 1.0 / maxf(0.001, ivl_air)
```
