## 详细方案

### 改动 1：稀有度底色分层（铺满 + 低饱和）

**问题**：现状底色是两条路径且都不按稀有度分层——
- PNG 框路径走 `CardFrameUi.subtle_panel_style()`（统一暗色 `Color(0.05, 0.08, 0.14, 0.92)`，稀有度仅靠 PNG 框线表达）
- fallback 路径走 `_apply_card_border_flat()`（底色 `Color(0.06, 0.10, 0.17, 0.95)` 固定，稀有度靠边框+glow）

两条路径的底色都没有按稀有度分层，这是"稀有度差异不明显"的真实根因。

**方案**：在 `card_frame_ui.gd` 新增 `rarity_panel_style(rarity)` 静态函数（带缓存），返回按稀有度分层的低饱和底色 StyleBoxFlat：

```
common:    Color(0.08, 0.10, 0.14)   # 基准暗灰蓝
uncommon:  Color(0.07, 0.12, 0.09)   # 暗绿底
rare:      Color(0.07, 0.10, 0.16)   # 暗蓝底
epic:      Color(0.10, 0.08, 0.16)   # 暗紫底
legendary: Color(0.14, 0.10, 0.06)   # 暗金底
mythic:    Color(0.15, 0.07, 0.11)   # 暗粉底
```

全部 alpha=0.95、corner_radius=6、保持各自路径原有的边框/glow 逻辑（不在底色函数里动边框，避免与现有 `_apply_card_border_flat` 的 glow 逻辑重复）。

**接入点（两条路径都改，统一来源）**：
- `CardFrameUi.apply_panel_with_frame()`（PNG 框路径）：把 `subtle_panel_style()` 替换为 `rarity_panel_style(rarity)` + 保留 PNG 框叠加
- `backpack_card_item.gd::_apply_card_border_flat()`（fallback 路径）：把 `panel_style.bg_color = Color(0.06, 0.10, 0.17, 0.95)` 改为从 `rarity_panel_style(c.rarity).bg_color` 取色，其余边框/glow 逻辑不变

**为什么低饱和**：底色之上还有 `CardBackgroundOverlay`（z_index=-1 势力底图，透明 PNG）+ `CardFrameOverlay`（z_index=30 稀有度框 PNG）。低饱和底色做"第三层编码"与这两层叠加后不会脏，而高饱和会打架。底色差异在暗环境下可感知但不刺眼。

**缓存**：`rarity_panel_style` 用 static var 字典缓存（key=rarity），避免每张卡每帧 new StyleBoxFlat。与现有 `_subtle_panel_style` / `_card_border_style_cache` 同模式。

### 改动 2：战斗卡 hover 动效（上浮 + 发光增强）

**现状**：`backpack_card_item.gd` 完全没有 `mouse_entered`/`mouse_exited` 连接（grep 确认）。hover 反馈只存在于拖拽时的相位仪目标槽位（`backpack_card_item_drag.gd`），卡牌本身无 hover 状态。

**方案**：在 `_ready()` 连接 `mouse_entered`/`mouse_exited` 信号：

```gdscript
mouse_entered.connect(_on_mouse_entered)
mouse_exited.connect(_on_mouse_exited)
```

新增两个方法：
- `_on_mouse_entered()`：
  - 受 `DesignTokens.is_motion_reduce()` 守卫，关闭时只切 hover 样式不做 Tween
  - Tween `position.y -= 2` + `scale *= 1.03`（0.1s EASE_OUT），模拟"上浮"
  - 切换 panel stylebox 为 hover 版（同名 `rarity_panel_style` 但 shadow_size +2、shadow_alpha +0.15，单独缓存 key 加 `_hover` 后缀）
- `_on_mouse_exited()`：反向 Tween 回原位 + 切回非 hover 样式

**关键实现细节**：
- hover 上浮用 `position` 偏移而非 `scale`——因为 BackpackCardItem 在 GridContainer 里，scale 不影响布局占位但视觉会"溢出"边界，position 偏移更可控。两者结合（小幅 scale + 微 position 偏移）。
- Tween 用 `create_tween()` 并行（`set_parallel(true)`）让位移和缩放同步。
- 池化复用风险：池化节点可能继承上一次的 hover Tween 状态。`set_card()` 复位时已在 `_add_card_item` 做 `modulate = Color(1,1,1,1)`，需补一条 `position/scale` 复位（在 `set_card` 开头或 `_add_card_item` 里加）。
- `mouse_filter` 现状：拖拽走 `gui_input`，默认 PanelContainer 的 mouse_filter 是 STOP，hover 信号能正常触发，无需改。

### 改动 3：Legendary/Mythic 脉冲发光（仅 hover 触发）

**范围**：仅 hover 时触发，不做 idle 常驻（用户确认，零 idle 性能开销）。

**方案**：在 `_on_mouse_entered()` 里，对 `c.rarity in ["legendary", "mythic"]` 的卡额外起一个循环 Tween：

```gdscript
if c.rarity == "legendary" or c.rarity == "mythic":
    _pulse_tween = create_tween().set_loops()
    _pulse_tween.tween_method(_set_glow_alpha, base_alpha, base_alpha + 0.2, 0.6)
    _pulse_tween.tween_method(_set_glow_alpha, base_alpha + 0.2, base_alpha, 0.6)
```

`_set_glow_alpha(a)` 重建当前 panel stylebox 的 shadow_color alpha（从缓存字典里取出当前 stylebox，改 shadow_color.a 后重新 override——注意要 `duplicate()` 出实例再改，不能改缓存里的共享对象）。

- `_on_mouse_exited()` 里 `_pulse_tween.kill()` 停止脉冲。
- 受 `DesignTokens.is_motion_reduce()` 守卫，关闭时脉冲不启动，只保留改动 2 的静态 hover 增强。
- 用 `tween_method` 而非 `tween_property`——因为 shadow_color.alpha 不是节点的直接 property，需要通过重建 stylebox 实现。

**为什么不在 idle 脉冲**：背包可能有 50+ 张卡实例（MAX_CARD_SLOTS=50），每张卡一个 idle 循环 Tween = 每帧 50+ 次 stylebox 重建，性能不可接受。仅 hover 时只有 1 张卡脉冲，零压力。

### 改动 4：空槽位 `+` 号标识

**现状**：`backpack_panel.gd::_get_empty_slot_style()` 返回半透明暗色 + 细灰边框的 Panel，无任何内容标识。`_ensure_min_card_slots()` 用这个 Panel 占位。

**方案**：给空槽位 Panel 加一个子 Label 显示 `+`：
- 在 `_ensure_min_card_slots()` 创建 placeholder 时，检查是否有子 Label，没有则 `add_child` 一个居中的 `+` Label（字号 20，颜色 `Color(0.4, 0.5, 0.6, 0.5)` 暗灰，mouse_filter=IGNORE）。
- 池化复用时 Label 已存在，直接 `visible = true`，不重复创建。
- placeholder 的 tooltip 设为"空格位"。

**不新建美术资源**：原方案要求 `empty_slot_plus.svg`，实际用 Label 字符 `+` 即可，零美术依赖，符合"最小改动"。

### 改动 5：新卡入场动画（淡入 + 回弹缩放）

**现状**：`_add_card_item()`（backpack_panel.gd:1256）添加卡后直接显示，无动画。

**方案**：在 `_add_card_item()` 末尾，对**新增**的卡（非池化复用的全部刷新）触发入场动画。为避免每次 rebuild 全部 50 张卡都动画（性能 + 视觉混乱），用 meta 标记区分：

- 池化复用的 item：`item.get_meta("_was_shown", false)` 为 true → 不动画，直接显示
- 新实例化的 item 或首次显示：动画
  ```gdscript
  item.modulate.a = 0
  item.scale = Vector2(0.85, 0.85)
  var t = create_tween()
  t.tween_property(item, "modulate:a", 1.0, 0.2)
  t.parallel().tween_property(item, "scale", Vector2(1,1), 0.25).set_trans(Tween.TRANS_BACK).set_ease(Tween.EASE_OUT)
  item.set_meta("_was_shown", true)
  ```

**关键**：动画后必须复位 `scale = Vector2(1,1)` 和 `modulate.a = 1.0`（EASE_OUT_BACK 会略微过冲再回弹，结束态是 1.0），避免残留。受 `is_motion_reduce()` 守卫，关闭时直接 modulate.a=1 无缩放。

**与改动 2 的 hover 动效兼容**：入场动画改的是 scale/modulate，hover 改的是 position/scale。两者不冲突——入场结束后 scale=1.0，hover 再在 1.0 基础上 ×1.03。但需确保入场 Tween 完成（用 `finished` 信号或就靠 0.25s 自然结束，hover 不会这么快触发）。

### 改动 6：标签切换微动效

**现状**：`_on_tab_changed()`（backpack_panel.gd:267）只做数据刷新，无视觉过渡。

**方案**：在 `_on_tab_changed()` 开头，对当前 tab 的 ScrollContainer 做一次透明度闪现：

```gdscript
var scroll = _tab_container.get_current_tab_control().get_node_or_null("ScrollContainer") # 或对应路径
if scroll and not DesignTokens.is_motion_reduce():
    var t = create_tween()
    t.tween_property(scroll, "modulate:a", 0.6, 0.05)
    t.tween_property(scroll, "modulate:a", 1.0, 0.15)
```

**防御性**：tab 控件结构因 tab 而异（RunesTab 是 HSplit 而非 ScrollContainer 直接子级），需 `get_node_or_null` 兜底，找不到就跳过动画不报错。受 `is_motion_reduce()` 守卫。

### 改动 7：稀有度色源收敛（前置清理）

**现状**：`modification_panel.gd` 有本地 `_rarity_color()`（lines ~1018-1026），6 档 RGB 值与 `GC.get_rarity_color` 不同（如 epic 本地 `Color(0.7, 0.4, 0.95)` vs GC `Color(0.48, 0.41, 0.93)`）。

**方案**：把 `modification_panel.gd::_rarity_color()` 改为直接转发 `GC.get_rarity_color(rarity)`，删除本地色值表。保留函数签名（调用方不动），只改函数体：

```gdscript
func _rarity_color(rarity: String) -> Color:
    return GC.get_rarity_color(rarity)
```

需在 modification_panel.gd 顶部确认 `GC` 已 preload（若无则加 `const GC = preload("res://resources/game_constants.gd")`）。

**为什么是前置**：本次虽然不重点改改造面板视觉，但收敛色源是后续任何"统一稀有度视觉"的基础。现在做掉，避免日后两个面板视觉不一致时再排查。

## 性能保证

- **零逐帧 `_draw()`**：所有效果用 StyleBoxFlat 缓存（static var 字典）+ Tween（一次性或 hover 触发）
- **零 idle Tween**：脉冲仅 hover 时 1 张卡，入场动画仅新增卡
- **池化安全**：所有 Tween 在 `_exit_tree` 或池化回收前需 kill；hover/入场状态在 `set_card` 复位
- **无障碍**：所有动效受 `DesignTokens.is_motion_reduce()` 守卫，关闭时退化为静态样式切换
- **缓存策略**：`rarity_panel_style(rarity)` + hover 版（`rarity_hover` key）两个 static 字典，复用现有 `_card_border_style_cache` 模式

## 风险与回滚

- **风险**：底色铺满可能与部分势力底图叠加后偏暗（如 `bg_void_research` 深紫色 + mythic 暗粉底）。**缓解**：底色 alpha 0.95 留 5% 透出势力底图，实机观察后可微调单档 alpha。
- **风险**：hover 上浮在 GridContainer 内可能被相邻卡遮挡（z_index）。**缓解**：hover 时 `z_index = 10`，退出时复位为 0。
- **回滚**：所有改动集中在 4 个文件，改动 1-3 在 `backpack_card_item.gd` + `card_frame_ui.gd`，改动 4-6 在 `backpack_panel.gd`，改动 7 在 `modification_panel.gd`。逐改动 git 可回滚，互不依赖（除改动 1 的底色函数被改动 2/3 的 hover 样式复用）。
