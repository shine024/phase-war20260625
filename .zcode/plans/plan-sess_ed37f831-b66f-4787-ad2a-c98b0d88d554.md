# 敌方相位师产兵层级递进 + 相位仪卡槽数限制产兵数

## 背景

用户两项诉求（基于 `scenes/units/enemy_phase_field_driver.gd`）：

1. **层级递进**：相位师符文加成/相位仪加成/强化等级不应总是 TIER_HIGH（最高）。当前：
   - L370 硬编码 `TIER_HIGH`（atk+35%/hp+30%/def+15%）给所有相位师产兵
   - L615 硬编码 `enhance_level=9`（满强化）给所有相位师产兵
   - `_apply_master_rune_bonus`(L711) 应用**全部** `_master_runes`，无 rune_count 限制
   - 应随关卡难度递进（低/中/高）

2. **卡槽数限制产兵数**：相位仪卡槽数 x 应限制产兵数 y。战斗卡可高级，但**数目受槽位限制**。

## 核心调查结论

| 事实 | 详情 |
|------|------|
| 当前 tier 硬编码点 | driver L370（产兵加成）+ L615（enhance_level）；2 处都是 `TIER_HIGH` |
| rune 无限应用 | `_apply_master_rune_bonus`(L711) 遍历**全部** `_master_runes`，无 rune_count 限制 |
| driver 无 game level | 只有 `master_config["level"]`（主等级 5-30），需经 setup 传入 |
| era_progress 公式 | `((game_level - 1) % 20) / 19.0` → 0.0~1.0（battle_spawn_system.gd:942-943 同款） |
| TIER 三档 | LOW(enh3/rune1/atk+10%/hp+10%) / MID(enh6/rune3/atk+20%/hp+18%) / HIGH(enh9/rune6/atk+35%/hp+30%) |
| 玩家侧槽位→单位映射 | `phase_instrument_manager.get_max_deployable_units()` → green 槽数（1槽=1单位，上限6）|
| 敌方侧现状 | 敌方相位仪 JSON **无 slots 字段**；`_unit_limit` 从 `stats.unit_limit`(5~15) 取，已 clamp 到 6（格子数限制）|
| `_unit_limit` clamp | L142: `mini(_unit_limit, BattleSlotGrid.SLOT_COUNT - 1)` = mini(_, 6) |

## 实施方案（3 阶段）

### 阶段1：游戏关卡传入 driver（基础设施）

**文件：`scenes/units/enemy_phase_field_driver.gd`**

setup() 增加从 master_config 读 game_level（兼容旧调用）：
- L115 `setup(master_config)` 内新增：
  - 读 `master_config.get("game_level", 0)` → 存入新字段 `_game_level: int = 0`
  - 新增字段声明：`var _game_level: int = 0`（与 `_master_stats` 等同级，约 L46 附近）
- 若 `_game_level > 0`，按 `((_game_level - 1) % 20) / 19.0` 算 `era_progress` → 存 `_era_progress: float`
- 否则 fallback：用主等级 `master_config["level"]`（5-30）粗映射到 0.0~1.0（`clamp((level-5)/25.0, 0, 1)`），保证旧路径不崩

**文件：`managers/game_manager.gd`**

`_build_garrison_config()`（L179-207）返回字典新增 `"game_level": current_level`：
- 在 L193 的 return 字典加一行 `"game_level": current_level,`
- 让驻守相位师把当前 game_level 透传给 driver

非驻守路径（`_enrich_master_config`）：同样补 `"game_level": current_level`（如有 return 点）。

### 阶段2：产兵 tier 按关卡递进（核心）★

**文件：`data/enemy_loadout_tiers.gd`**

新增专门给相位师用的 tier 选择函数（不改原 `get_tier_for_level_progress`，避免破坏普通敌兵）：
```gdscript
## v7.x: 相位师产兵 tier 按关卡难度递进（替代旧"恒定 TIER_HIGH"）
## 时代早期（关卡1-6）→LOW, 中段（7-14）→MID, 后期/Boss（15-20）→HIGH
## 相位师基准偏高一档：早期也至少 MID（相位师比普通兵强）
static func get_phase_master_tier(era_progress: float) -> int:
    if era_progress < 0.30:
        return TIER_MID   # 时代早期：中配（相位师最低保障）
    elif era_progress < 0.70:
        return TIER_MID   # 时代中段：中配
    else:
        return TIER_HIGH  # 时代后期/Boss 关：高配
```
**设计决策**：相位师 tier 比普通敌兵高一档保底（早期也至少 MID，不会 LOW），但不再是恒定 HIGH。19 驻守关分布：WW1早期(L10,era_progress 0.47)→MID，WW1后期(L20,era_progress 1.0)→HIGH...，末关/时代 Boss 关走 HIGH，符合"难度递进"。

**文件：`scenes/units/enemy_phase_field_driver.gd`**

**(a) enhance_level 改 tier 派生（L614-615）**：
```gdscript
# 旧：c.enhance_level = int(EnemyLoadoutTiers.get_bonus_for_tier(EnemyLoadoutTiers.TIER_HIGH).get("enhance_level", 0))
# 新：
var _pm_tier: int = EnemyLoadoutTiers.get_phase_master_tier(_era_progress)
c.enhance_level = int(EnemyLoadoutTiers.get_bonus_for_tier(_pm_tier).get("enhance_level", 0))
```

**(b) 产兵加成改 tier 派生（L369-388）**：
```gdscript
# 旧：var _high_bonus: Dictionary = _ELT.get_bonus_for_tier(_ELT.TIER_HIGH)
# 新：缓存 _pm_tier（setup 时算一次），用 get_bonus_for_tier(_pm_tier)
var _pm_bonus: Dictionary = _ELT.get_bonus_for_tier(_pm_tier)
```
其余 hp/atk/def 乘区逻辑不变，只是数值来源从 TIER_HIGH → _pm_tier。

**(c) 符文按 tier 限量应用（`_apply_master_rune_bonus` L711）**：
```gdscript
func _apply_master_rune_bonus(stats: UnitStats) -> void:
    if _master_runes.is_empty():
        return
    # v7.x: 按 tier 限量应用符文（LOW=1/MID=3/HIGH=6）
    var _rune_cap: int = int(EnemyLoadoutTiers.get_bonus_for_tier(_pm_tier).get("rune_count", 99))
    var _applied: int = 0
    for rune_id in _master_runes:
        if _applied >= _rune_cap:
            break  # 超出 tier 上限的符文不应用
        # ... 原 match 逻辑不变
        _applied += 1
```
**设计决策**：符文按稀有度排序后取前 N 个（高稀有度优先）。`_master_runes` 来自 `_derive_runes`（已按 level 选稀有度梯度），顺序天然偏稀有度优先，直接 slice 前 rune_count 个即可。

setup() 末尾缓存 `_pm_tier`：
```gdscript
_pm_tier = EnemyLoadoutTiers.get_phase_master_tier(_era_progress)
```

### 阶段3：相位仪卡槽数限制产兵数 ★

**文件：`data/json/enemy_phase_instruments.json`**

为每个敌方相位仪补 `unit_capacity`（产兵上限）字段。按 level/rarity 派生（mk1=3, mk2=4, mk3=5, mk4=6, god=6），共 26 条记录各加一个整数字段。

**文件：`data/enemy_phase_equipment.gd`**（或读取 JSON 的入口）

`get_phase_instrument(id)` 返回字典天然带 `unit_capacity`（JSON 直读，无需改 loader）。

**文件：`scenes/units/enemy_phase_field_driver.gd`**

setup() 内 `_unit_limit` 计算改用相位仪 capacity（最小约束）：
```gdscript
# L138-142 旧：
# _unit_limit = int(_master_stats.get("unit_limit", 5))
# _unit_limit = mini(_unit_limit, BattleSlotGrid.SLOT_COUNT - 1)
# 新：取 stats.unit_limit 和 phase_instrument.unit_capacity 的最小值
_unit_limit = int(_master_stats.get("unit_limit", 5))
var _inst_id: String = String(_equipment.get("phase_instrument", ""))
if not _inst_id.is_empty():
    var _inst_cfg: Dictionary = EnemyPhaseEquipment.get_phase_instrument(_inst_id)
    var _cap: int = int(_inst_cfg.get("unit_capacity", 0))
    if _cap > 0:
        _unit_limit = mini(_unit_limit, _cap)  # 相位仪卡槽数限制产兵数
_unit_limit = mini(_unit_limit, BattleSlotGrid.SLOT_COUNT - 1)  # 格子数硬上限不变
```

**设计决策**：
- 相位仪 capacity 是产兵上限的**附加约束**（与 stats.unit_limit 取最小）
- 数值校准：早期驻守师 mk1(cap 3) → 产兵 3 个；中期 mk2/mk3(cap 4~5) → 4~5 个；后期 mk4/god(cap 6) → 6 个满配
- 既体现"卡槽数限制产兵数"（x→y 关系），又不破坏格子数物理上限（6）
- 高级战斗卡（platforms 里的 archetype）数值不变，只是数量被 capacity 卡住——符合用户"卡可高级但数目受限"

## 影响面核对

| 系统 | 影响 |
|------|------|
| 普通敌兵波次 | **无影响**（走 `get_tier_for_level_progress(era_progress, false)`，本方案不改该函数）|
| 驻守相位师（19关） | enhance/rune/tier 随关卡递进；产兵数受 capacity 限制 |
| 随机遭遇相位师（11关池）| 同上（`_enrich_master_config` 也补 game_level）|
| master_power_evaluator | **无影响**（读原始 config dict 评分，不读产兵 tier）|
| 玩家侧 | **无影响**（玩家走 `get_max_deployable_units` 独立链路）|
| 存档 | **无影响**（纯运行时派生，不持久化）|

## 向后兼容

- `setup()` 新增 `game_level` 字段用 `.get("game_level", 0)`，旧调用（无此字段）fallback 到主等级映射，不崩
- `_build_garrison_config` 加字段是字典扩展，旧消费者不读该字段不受影响
- JSON 加 `unit_capacity` 字段，`.get("unit_capacity", 0)` 缺省 0 时不约束（旧相位仪无此字段→行为不变）
- `_pm_tier` 缓存在 setup 末尾，若 `_era_progress` 算不出（极端 fallback）仍能给合理值
