# 三套卡牌数据源统一重构方案

## 问题根因
游戏有**三套并行卡牌数据源**，数值量级严重不统一：
- **玩家原生卡** `default_cards.gd`（虚空领主 HP 2200，高量级）
- **缴获卡** `captured_card_stats.gd`（虚空领主 HP 240，复刻敌方低量级）← **bug 源头**：进玩家背包后只有 240 血
- **敌方原型** 5个分散来源（JSON / `_get_foe_stats` / `_pool_stats_for_kind` / 反向依赖缴获卡），量级混乱

## 统一目标（已与用户确认）
1. **缴获卡=敌方原型真身**：消灭 `captured_card_stats.gd` 独立数据，缴获卡直接克隆敌方 archetype
2. **玩家+敌方统一一套数据**：同一概念卡的 base_hp 一致，敌方额外叠 wave/level/master/faction 难度乘区
3. **base_hp 重新标定中间值**：按单位档次重标定（普通80-200/精英300-600/boss800-1500/终极1500），避免极端

---

## 架构决策：单一真值源 = 统一卡牌表（UnifiedCardTable）

**新建 `data/unified_card_table.gd`** 作为唯一数据源，替代当前三套：

```
┌─────────────────────────────────────────────┐
│  unified_card_table.gd （唯一真值源）         │
│  - ~150 个概念卡，每个含完整三维攻防/HP/字段  │
│  - 按 era + combat_kind + tier 组织          │
│  - 标定后的中间值 base_hp                    │
└───────────────┬─────────────────────────────┘
                │ 三个消费者各自派生
    ┌───────────┼───────────┐
    ▼           ▼           ▼
玩家原生卡    敌方原型     缴获卡
(直接用)     (叠难度乘区)  (克隆敌方原型)
```

**字段统一为玩家卡口径**（CardResource 三维攻防 + range_value格数 + attack_speed次/秒 + 4值weapon_type），因为：
- 玩家卡字段最完整（三维攻防/per-target攻速/weapon_names）
- `build_stats_from_card` 已是成熟入口，敌方/缴获都走它最统一
- 字段转换公式已存在（`captured_unit_cards.gd:83-140`），可复用

---

## 标定规则（按 combat_kind + tier）

| 单位档次 | base_hp 范围 | 示例 |
|---------|-------------|------|
| 普通轻装/步兵 | 80-180 | ww1步兵40→100, 近未来机械步兵100→150 |
| 普通载具/支援 | 150-350 | 悬浮坦克250→300, 自行火炮200→280 |
| 精英单位 | 300-600 | T-72 375→450, 巨神机甲600→800 |
| Boss（时代守护者） | 800-1500 | 虎王800→1000, 风暴核心1800→1200 |
| 终极单位 | 1200-1800 | 虚空领主统一到~1500 |
| 堡垒 | 600-2500 | 碉堡600→800, 能量护盾3000→2500 |

**标定原则**：取当前三套的**中位数**向上靠档，既解决"缴获卡太脆"，也避免"玩家裸卡2200太肉"。攻击/防御数值同步等比缩放到新 HP 量级。

## 实施阶段（6阶段，按依赖顺序）

### 阶段1：建立统一卡牌表（核心）
- **新建 `data/unified_card_table.gd`**：含 ~150 个概念的完整字段（合并当前 default_cards 110张 + 敌方独有53张 - 重叠38张）
- 每个概念字段：card_id, display_name, era, combat_kind, base_hp(标定值), attack_light/armor/air, defense_light/armor/air, range_value(格), attack_speed, weapon_type(4值), deploy_speed, base_speed, power, weapon_label, tier(普通/精英/boss/终极)
- **数据迁移**：从现有三套数据取值，按标定规则调整 base_hp，攻击/防御等比缩放
- **提供查询接口**：`get_card(card_id)`, `get_all_cards()`, `get_cards_by_era(era)`, `get_cards_by_tier(tier)`

### 阶段2：玩家原生卡改读统一表
- **改 `data/default_cards.gd`**：`create_all_cards()` / `_unit()` 改为从 `UnifiedCardTable` 读取数据构造 CardResource（保留现有 CardResource 字段映射）
- 现有 `get_card_by_id` / `_id_lookup_cache` / `register_dynamic_card` 机制保留（这是缴获卡注册入口，阶段4还要用）
- 验证：玩家卡商店/背包/养成面板数据来源不变，只是底层从硬编码 `_unit()` 改为读统一表

### 阶段3：敌方原型改读统一表
- **改 `data/enemy_unit_manifest.gd`**：
  - `_get_foe_stats`（A/B段34张）→ 从 UnifiedCardTable 读对应 card_id，转换字段（range_value→attack_range像素, attack_speed→attack_interval秒）
  - `_pool_stats_for_kind`（D段29张）→ 废弃 kind 公式，每个 pool 单位从统一表读真实数据（D段29个概念已在阶段1录入统一表）
  - `_make_fort_row`（E段10张）→ **解除对 CapturedCardStats 的反向依赖**，改从 UnifiedCardTable 读
- **改 `data/enemy_archetypes.gd` / JSON**：C段36张固定敌人的 base_hp 改从 UnifiedCardTable 读（JSON 保留作 fallback，但 hp/攻击字段由统一表覆盖）
- 验证：敌方单位战场 HP = 统一表 base_hp × wave/level/master/faction 乘区（`enemy_stat_resolver.resolve_classic_enemy` 不变，只是 cfg.hp 来源变了）

### 阶段4：缴获卡改等于敌方原型（消灭独立数据）
- **改 `data/captured_unit_cards.gd`**：
  - `register_into_default_cards_cache()` 不再遍历 manifest 重新构建缴获卡
  - 改为：缴获卡 drop_card_id 直接**指向统一表的 card_id**（去掉 captured_ 前缀间接层）
  - `_build_captured_card` → 直接 `DefaultCards.get_card_by_id(unified_card_id).clone()`（克隆统一表卡牌，含标定后的完整数值）
- **改 `data/enemy_unit_manifest.gd`** 的 `captured_card_id_for`：archetype 的 drop_card_id 直接返回统一表 card_id（不再加 captured_ 前缀）
- **`captured_card_stats.gd` 标记 deprecated**：保留文件但内容清空或改为从统一表派生（向后兼容旧存档的 captured_* card_id 查询）

### 阶段5：掉落链路与存档兼容
- **改 `scripts/card_drop_grants.gd`** / `managers/drop_manager.gd`：on_kill 掉落时，drop_card_id 已是统一表 card_id，直接 `InstanceRegistry.create_instance(card_id)` 进背包
- **存档迁移**（`scripts/systems/save_migration.gd` 新增 v7 迁移）：
  - 旧存档的 captured_* card_id 实例 → 映射到统一表 card_id（如 `captured_foe_fut_arm_nexus` → `fut_arm_nexus`）
  - 旧存档的 captured_* 实例养成数据（enhance_level/mods）保留，只换 card_id 指向
  - 迁移映射表放在 `data/captured_card_migration_map.gd`

### 阶段6：数值标定与平衡验证
- 按5个时代 × 5个档次批量标定统一表 base_hp
- 攻击/防御数值等比缩放（保持 DPS/HP 比率）
- 用 `balance-check` skill 验证：玩家卡 vs 敌方（叠乘区后）vs 缴获卡三者量级关系合理
- Godot --check-only 验证 + 关键卡数值核对

## 关键设计决策
1. **统一表用玩家卡字段口径**（三维攻防/range_value格数）—— 最完整，转换公式已存在
2. **敌方仍叠难度乘区**（wave×level×master×faction）—— 不改 `enemy_stat_resolver`，只改 cfg.hp 来源
3. **缴获卡=克隆统一表卡** —— 与商店买的同名卡数值完全一致，彻底解决"263血废卡"
4. **D段废弃kind公式** —— 29个补充单位各录真实数据进统一表
5. **E段解除反向依赖** —— 堡垒数据从统一表读，不再依赖 captured_card_stats
6. **存档迁移保养成** —— 旧 captured_* 实例的强化/改造数据迁移到新 card_id，不丢玩家进度

## 影响范围
- **新增**：`data/unified_card_table.gd`, `data/captured_card_migration_map.gd`
- **改造**：`default_cards.gd`, `enemy_unit_manifest.gd`, `enemy_archetypes.gd`, `captured_unit_cards.gd`, `card_drop_grants.gd`, `drop_manager.gd`, save_migration
- **标定废弃**：`captured_card_stats.gd`（内容清空，保留壳兼容）
- **不动**：`build_stats_from_card`（已是统一入口）、`enemy_stat_resolver`（乘区链不变）、养成面板（数据源不变）、InstanceRegistry（实例化机制不变）

## 验证
- Godot headless --check-only（133+卡构建无语法错误）
- Grep 链路核对（UnifiedCardTable 查询接口全链路调用配对）
- 数值核对：虚空领主统一后 base_hp≈1500（玩家/缴获一致），敌方第80关≈4260血（叠乘区后）
- 存档迁移：旧 captured_* 实例能正确映射到统一 card_id 且养成数据保留
