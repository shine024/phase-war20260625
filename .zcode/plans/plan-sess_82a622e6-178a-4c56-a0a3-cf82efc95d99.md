# Phase War 游戏深度提升 - 实施计划（6 子项 / 5 批次）

## 总览

诊断结论：游戏"玩法简单没吸引力"的根因是——战斗中决策点过少、普通敌人纯数值差异无机制、关卡无特殊约束、通关后缺乏独占收集驱动。

本计划实施 6 个子项，按风险/独立性分 5 批次。每批独立可验证、可上线，互不阻塞。全部向后兼容（新字段 `.get(key, default)`，缺省回退旧行为）。

| 批次 | 子项 | 工作量 | 风险 | 依赖 |
|------|------|--------|------|------|
| 1 | 反应式AI + antitank/fast-stealth 行为 | 小 | 极低 | 无 |
| 2 | 精英词缀系统 | 中 | 低 | 无 |
| 3 | 关卡机制（限定兵种/能量惩罚/特殊胜利） | 中 | 低 | 无 |
| 4 | 可部署格子差异化 | 中高 | 中 | 无（可独立） |
| 5 | 独占奖励（成就/挑战/改造/特殊卡） | 中 | 低 | 无 |

## 批次1：敌人行为激活（反应式AI + antitank/fast-stealth）

### 1A. 反应式 AI — 相位师侦测玩家阵容出克制兵
**目标**：相位师产兵时扫描玩家主力兵种，70% 概率出克制兵，30% 跟原序列（保留节奏）。

**改动**：
- `scenes/units/enemy_phase_field_driver.gd`（选 platform 处 `:326-339`）：
  - 新增 `_tally_player_combat_kinds() -> Dictionary`：遍历 `BattleManager.get_cached_nodes_in_group("player_units")` 读 `unit.stats.combat_kind` 统计分布（≤6 单位，O(1)）
  - 新增 `_counter_kind_for(player_kind) -> int`：反查克制表（ARMOR→出SUPPORT/FORT，AIR→出AIR，LIGHT→出ARMOR）
  - 新增 `_pick_reactive_platform(valid_platforms, seq_entry)`：70/30 软偏好，筛选 combat_kind 匹配的候选 platform，空则回退原序列
  - 在选 platform 前调用，序列 entry 的 `reactive_chance` 字段（可选）控制不同相位师的"聪明度"

**复用**：克制关系直接用 `enemy_stat_resolver.gd:189-218` 的 combat_kind→三维攻击比例（SUPPORT/FORT 对装甲强、AIR 对空中强），无需新建表。

### 1B. antitank 索敌 — 反坦克单位优先打装甲
**目标**：带 `antitank` tag 的敌人优先攻击 ARMOR 类（目前纯死字段）。

**改动**：
- `scripts/battle/target_selection.gd` `_get_counter_priority`（`:92-99`）：函数签名加 attacker tags 参数，命中 `antitank` 强制返回 ARMOR
- `scenes/units/enemy_unit.gd` `_find_target`：曲射分支（`:767-774`）传入 tags；直射分支（`:724`）对 antitank 单位改走 `_collect_player_candidates` + ARMOR filter

### 1C. fast/stealth 行为（路径B：纯数值，不解锁槽位吸附）
**目标**：激活 fast/stealth 两个死 tag，用数值差异而非真移动（零视觉风险，不破坏格子战范式）。

**改动**：
- `scenes/units/enemy_unit.gd`：
  - **fast**（`_apply_archetype_stats` `:318` 附近）：命中 `fast` tag → attack_interval ×0.80（攻速+20%）+ 开局部署到最前槽位（slot 0，靠中线，更早接敌）
  - **stealth**（`_find_target`）：复用 `construct_unit_ai.gd:211-239` `_scan_slot_targets` 的 L1/L2 优先级链（优先打指挥 platform_type==12 / 光环单位 AURA_PLATFORM_TYPES）+ 开局短暂减伤（前 4 秒 damage_taken ×0.6，模拟"潜入到位"）
  - 新增 `_has_behavior_tag(tag)` 辅助 + `_behavior_init` 在 setup 末尾做一次性部署位置调整

**向后兼容**：仅 10 个敌人有 fast、1 个有 stealth，默认行为不变；无 tag 的敌人完全不受影响。

**验证**：smoke test（参考 `tests/master_power_smoke.gd` 模式）验证反应式选择分布 + antitank 索敌优先级 + fast 攻速倍率；Godot `--check-only`。

## 批次2：精英词缀系统

**目标**：让普通波次敌人也有机制差异（暗黑式词缀怪），精英/boss 波随机获得 1-3 词缀。

### 2A. 新建敌人词缀定义表
**新文件 `data/enemy_affixes.gd`**（参考 `data/affix_definitions.gd` 结构）：
- ~12 个词缀，3 档稀有度（common/rare/elite-only）
- **common**（数值强化）：狂暴(attack_damage+30%)、坚韧(max_hp+60%)、加速(attack_interval-20%)、吸血(lifesteal+15%)
- **rare**（机制）：连锁(chain_chance+30%)、溅射(splash_damage)、暴击(crit_chance+25%)、护盾(shield_on_kill)、闪避(dodge_chance+20%)、回血(hp_regen)
- **elite-only**（boss trait 平移）：反伤(armor_reflect)、限伤(damage_cap)、免死(cheat_death_chance 一次)
- 复用玩家词缀 `effect_key` 命名空间（`AffixCombatHandler` 零改动通用）；按 `combat_kind` 过滤（连锁只给远程、反伤只给装甲/堡垒）

### 2B. 词缀分配接入两条波次链路
**经典波次路径**：
- `data/level_spawn_sequences.gd` WaveSpec（`:128-136`）：新增 `affix_slots: int`（精英波=1、boss 波=2）+ `affix_rarity_pool: Array`
- `managers/battle/battle_spawn_system.gd` `spawn_card_grid_enemy_wave`（`:314` 前）：按 wave_spec.affix_slots 调 `EnemyAffixes.roll_affixes()` 得词缀列表
- `scenes/units/enemy_unit.gd` `setup`：新增 `apply_enemy_affixes(affixes)`，构造 UnitStats 后调 `AffixManager` 注入；战斗效果走现成 `AffixCombatHandler`

**相位师产兵路径**：
- `scenes/units/enemy_phase_field_driver.gd` `_produce_unit_with_equipment`（`:418` `_apply_sequence_entry_bonus` 后）：序列 entry type=elite roll 1 词缀、type=boss roll 2 词缀

### 2C. 词缀视觉区分 + 信息显示
- `scripts/card_grid_mod_strip.gd`：词缀怪加边框色（common 蓝/rare 紫/elite 橙）+ 词缀图标
- `scenes/ui/card_info_panel.gd`：`_show_generic_enemy_unit` 显示词缀列表（复用 `_translate_mod_key` 翻译表，v7.x 已补齐 70 key）

**新文件**：`data/enemy_affixes.gd`、`tests/enemy_affix_smoke.gd`

**验证**：smoke test 验证词缀 roll 分布 + effect_key 应用正确；Godot `--check-only`；实机看词缀怪视觉。

## 批次3：关卡机制（限定兵种/能量惩罚/特殊胜利）

**目标**：让特定关卡有"必须改变策略"的硬约束。

### 3A. 关卡数据扩展
**改动 `data/level_information.gd`**：`_level_db` 每关新增可选 `"special_rules": {}` 字段（结构参考死数据 `challenge_definitions.gd` 的 rules+bonus_objectives）：
```
{
  "restrict_platforms": [3,5],     # 限定可部署兵种类型（空=不限）
  "energy_mult": 0.5,              # 能量上限/开局乘率（1.0=正常）
  "energy_regen_mult": 0.5,        # 能量回复乘率
  "win_type": "survive_waves",     # 特殊胜利：survive_waves=坚守N波/protect_target=护送/kill_priority=击杀优先目标
  "win_param": 5,                  # 胜利参数（survive_waves 的波数）
  "deploy_limit": 4                # 本关部署上限（默认6）
}
```
字段全可选，缺省=普通关。先给 10-15 个关键关挂规则（每时代 Boss 关 + 时代首关 + 中段关卡），其余渐进铺。

### 3B. 逻辑层挂接（4 个挂点）
- **限定兵种**：`managers/battle/battle_spawn_system.gd` `request_player_deploy`（`:489` 拿到 platform_card 后）加类型校验，仿 `phase_law_manager.gd:407` law_families 范式；不通过调 `_emit_deploy_failed`（`:999` 现成）
- **能量惩罚**：`managers/energy_manager.gd` `start_battle`（`:40`）读 special_rules.energy_mult 覆盖 `_max`/`_base_start`；`_apply_instrument_energy`（`:86`）末尾乘 regen_mult
- **特殊胜利**：`managers/battle/battle_manager.gd` `_check_win_lose`（`:472`）插分支——survive_waves 达到 win_param 波且存活判胜；protect_target 某单位存活 N 秒判胜
- **部署上限**：`request_player_deploy` 的上限检查读 special_rules.deploy_limit（覆盖默认 6）

### 3C. UI 反馈
- `scenes/world_map.gd` `_collect_level_info` / `_show_level_info_popup`：关卡弹窗显示特殊规则（限定兵种/能量减半/胜利目标）+ 警示色
- `scenes/ui/bottom_instrument_bar.gd`：战斗 HUD 顶部显示本关约束条 + 胜利目标；被限定的兵种卡标灰禁用

**向后兼容**：special_rules 缺省空字典=普通关；旧存档零影响。

**验证**：smoke test 验证 4 个挂点各自生效；Godot `--check-only`；实机验证关键关约束。

## 批次4：可部署格子差异化

**目标**：让"在哪格部署"变成策略——不同槽位有不同效果（前排加攻/后排加防/能量节点回能等）。

### 4A. 新建槽位属性系统
**新文件 `data/slot_modifiers.gd`**：
- 定义槽位效果类型：`attack_bonus`(攻击+%) / `defense_bonus`(防御+%) / `energy_regen`(回能) / `deploy_discount`(部署减能) / `cover`(减伤%)
- `derive_slot_role(slot_index, side)` → 基于槽位离中线距离推导前排/中排/后排（玩家 slot 5-6=前排、3-4=中排、0-2=后排，敌方镜像）
- `get_slot_modifier(level, slot_index, side)` → 读 LevelInformation 的 slot_layout 规则（可选关卡级覆盖），返回该槽位的修饰符字典
- 默认布局：前排 attack_bonus+15%（肉盾/突击位）、后排 defense_bonus+15%/cover+10%（射击位），无规则时返回空（向后兼容）

### 4B. 槽位效果接入
- `scenes/units/construct_unit.gd` `setup`（部署完成后）：读 `get_meta("card_grid_slot")` → 调 `SlotModifiers.get_slot_modifier()` → 应用到 stats（attack/defense/cover 等乘区）
- `managers/battle/battle_spawn_system.gd` `request_player_deploy`（`:446`）：部署成功后把槽位修饰符传入 unit
- `scenes/battlefield/battle_slot_grid.gd` `_rebuild_centers`（`:44`）：槽位渲染时读修饰符上色/标图标（前排红、后排蓝、能量节点金）

### 4C. 部署 UI 显示槽位属性
- `scenes/ui/bottom_instrument_bar.gd` 待部署态：高亮目标槽位时 tooltip 显示该槽位效果
- `scenes/ui/battle_click_overlay.gd`：悬停槽位显示效果提示

**与批次3协同**：关卡 special_rules 可含 `slot_overrides` 字段覆盖默认槽位布局（如某关"中间格子是能量节点，部署在此回能+50%"），让关卡机制和格子差异化联动。

**验证**：smoke test 验证槽位角色推导 + 修饰符应用；Godot `--check-only`；实机看槽位着色与效果。

## 批次5：独占奖励（成就/挑战/特定改造/特殊卡）

**目标**：给玩家明确的"为这个去玩"的独占收集目标，解决通关后动力不足。

### 5A. 统一奖励格式（前置修复）
**现状问题**：`achievement_definitions.gd` 用 `{nano_materials: N}` 格式，但 `achievement_rewards.gd` 期望 `{type, amount, card_id}` 格式，两者不兼容。
- **改动 `data/achievement_definitions.gd`**：reward 字段统一为 `{type, amount, card_id?, unlock?}` 格式，type 支持 `nano`/`rep`/`card`/`mod_blueprint`/`unlock_card`/`unlock_mod`
- **改动 `managers/achievement/achievement_rewards.gd`**：grant() 兼容新旧两种格式（读 type 字段分流，缺省按 nano 处理保旧成就）

### 5B. 新增独占奖励内容
- **特殊卡（独占收集）**：`data/default_cards.gd` 新增 5-8 张独占卡（如"时代守护者"系列，击败各时代相位师解锁），高战力/独特外观，仅通过成就/挑战获得、不可商店购买
- **特定改造（独占养成）**：`data/modification_modules/` 新增 6-8 个独占改造（如"相位共鸣"系列），仅挑战模式奖励
- **更新成就/挑战定义**：`achievement_definitions.gd` + `challenge_definitions.gd` 给关键成就挂独占奖励（击败时代Boss→该时代守护者卡；挑战大师→独占改造）

### 5C. 奖励发放接入
- `managers/drop_manager.gd` 已支持 `grant_dropped_cards_by_id`（`:167`）发指定卡——独占卡奖励走此路径
- 改造蓝图走 `IntelItemBag.add_item`（`drop_manager.gd:419` 现成）——独占改造蓝图同路径
- 新增 `unlock` type：解锁型（标记 flag，商店/BP 解锁该卡可购买/可掉落），存档到 BlueprintManager 的 unlocked 集合

### 5D. UI 展示独占内容
- `scenes/ui/achievement_panel.gd`：奖励图标区分（卡牌图标/改造图标/资源图标）
- `scenes/ui/card_info_panel.gd`：独占卡显示"成就/挑战独占"标签 + 获取途径提示

**向后兼容**：旧成就缺省 type 按 nano 处理；独占卡/改造新定义不影响现有卡池。

**验证**：smoke test 验证奖励格式兼容 + 发放链路；Godot `--check-only`；实机看成就奖励发放。

## 横切关注点

**向后兼容**：全部新字段 `.get(key, default)`，缺省回退旧行为；词缀/反应式/特殊规则/槽位修饰全可选，旧存档零影响。

**文档**：每批次完成后更新 AGENTS.md（沿用 v6.x/v7.x 记录格式：改动点表 + 设计决策 + 验证）。

**预计每批次规模**：批次1（~3文件）/ 批次2（~5文件+2新文件）/ 批次3（~5文件）/ 批次4（~5文件+1新文件）/ 批次5（~6文件）。
