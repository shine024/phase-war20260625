# 改造面板重构 · 按设计稿 v1.4 实施

## 目标
按 `docs/design_mockups/改造面板重设计_底部操作台_右单位面板.html`（v1.4）重构游戏内 `modification_panel`。

## 当前 vs 目标结构对照

```
【当前】                          【目标 v1.4】
左栏 220px                        左栏 290px（加宽）
中栏：列头+9槽位条+改造库          中栏：列头+改造库+底部操作台（删9槽位条）
右栏：CardView⇄ModDetailsPanel    右栏：恒定单位面板（战力/5档/属性/已装列表）
   （互斥切换）                       （不再切换）
```

## 改动清单

### A. tscn 结构改动（`scenes/ui/modification_panel.tscn`）

**A1. 三栏宽度**：左栏 `custom_minimum_size` (220,0)→(290,0)；右栏保持 (300,0)（设计稿 280，但游戏内 300 更稳，差异极小）

**A2. 中栏删除 9 槽位横排条**：删除 `SlotVisualSection`（L391-417）整个子树（SlotVisualTitle + SlotVisualHost）。`_refresh_slot_visual()` 函数同步删除。

**A3. 中栏新增底部操作台**：在 MiddleVBox 末尾（ModScrollContainer 之后）新增 `ActionDeck`（PanelContainer，cyan 顶部边框）：
- `ActionEmpty`（默认显示）：引导文字"点击上方改造模块库..."
- `ActionBody`（选中时显示）：
  - 左块 `DeckLeft`：模块图标 + 名+稀有度 + 核心属性行（+42%）+ 要求行（强化≥3✓ 纳米✓ 图纸✓）
  - 右块 `DeckRight`：`InstallButton`（大号 cyan 按钮）+ 副按钮
- 布局：中栏整体改为「改造库 flex 按内容高度 + 操作台紧跟」，操作台不贴面板底（设计稿要求"模块信息更上一点"）

**A4. 右栏重构为恒定单位面板**：`DetailPanel` 下删除 CardView/ModDetailsPanel 互斥切换结构，改为单一 `UnitPanel`（VBoxContainer）：
- `UnitHero`：缩略图 + 名#实例号 + 标签（时代/兵种/档位）
- `PowerBlock`：战力大字 + 档位名
- `TierProgress`：5 档进度（用现有 `GeoShapes.TierLadder` 或 5 个 chip）
- `StatGrid`：基础属性 6 格（HP/轻攻/甲攻/空攻/装甲防/移速）
- `InstalledList`：已装改造列表（复用现有 `_refresh_installed_list` 逻辑，含启用/禁用切换）

**A5. 保留的节点**：标题栏 / 资源条 / ResultLabel / 左栏名册+筛选 / 中栏列头+改造列表 —— 结构不动，只可能微调宽度。

### B. gd 逻辑改动（`scenes/ui/modification_panel.gd`）

**B1. 删除**：
- `_refresh_slot_visual()`（L647-683）—— 9 槽位横排已删
- 相关 @onready：`slot_visual_title` / `slot_visual_host`
- 三处对 `_refresh_slot_visual()` 的调用

**B2. 改造右栏刷新**：
- `_update_card_info()`（L596-643）→ 重命名为 `_refresh_unit_panel()`，不再做 CardView/ModDetailsPanel visible 切换，改为填充右栏单位面板各字段：
  - 战力：`EvolutionHelpers.estimate_power_score(key, BlueprintManager)`（复用现有 L706 写法）
  - 档位：`PowerTiers.get_tier_by_power(power)` + `get_tier_name` + `get_tier_color`（复用 `_get_card_tier_str`）
  - 属性：`selected_card.get_modified_stats()`（复用现有 `_build_stat_delta_preview` 的取数方式，返回 Dictionary 含 max_hp/attack_*/defense_*/move_speed）
  - 已装列表：复用 `_refresh_installed_list()` 逻辑（挂载点改到右栏 UnitPanel/InstalledList）

**B3. 新增底部操作台刷新**：
- 新增 `_refresh_action_deck(mod_data)` 函数（替代原 `_show_mod_details` 的右栏切换部分）：
  - 选中模块时：`ActionEmpty.visible=false`，`ActionBody.visible=true`，填充图标/名/核心属性/要求/安装按钮
  - 未选模块时（`_on_card_selected` 后 `selected_mod_id=""`）：`ActionEmpty.visible=true`，`ActionBody.visible=false`
- 战力档位阶梯：原 `_render_tier_ladder()` 逻辑保留，挂载点从右栏 ModDetailsPanel 改到操作台内部（或操作台中块）
- InstallButton 重连逻辑（L1010-1016 disconnect+connect）保留，按钮节点路径改为操作台内

**B4. 节点引用更新**：
- 删除：`%CardView` / `%ModDetailsPanel` / `%InfoLabel` / `%InstalledTitle`（原 CardView 子节点）/ `%SlotVisualTitle` / `%SlotVisualHost`
- 新增 @onready：操作台相关（`%ActionEmpty` / `%ActionBody` / `%DeckNameLabel` / `%DeckCoreLabel` / `%DeckReqLabel` / `%DeckInstallButton`）+ 单位面板相关（`%UnitHeroName` / `%UnitPowerVal` / `%UnitTierName` / `%UnitStatGrid` / `%UnitInstalledList`）
- 保留：`%InstalledList`（路径从 CardView 改到 UnitPanel）、`%TierLadderContainer`（移到操作台）、`%NameLabel`/`%EffectsLabel` 等（移到操作台或用新节点名）

### C. 数据链路（全部复用现成 API，无需新写）

| 设计稿元素 | 数据源 | 调用方式 |
|---|---|---|
| 战力评分 | `EvolutionHelpers.estimate_power_score(key, BlueprintManager)` | key=instance_id 优先，复用 L706 |
| 5档进度 | `PowerTiers.get_tier_by_power(power)` + `POWER_THRESHOLDS=[150,260,420,720]` | 复用 `_render_tier_ladder` |
| 基础属性6格 | `card.get_modified_stats()` → Dictionary | 复用 `_build_stat_delta_preview` 取数 |
| 已装改造列表 | `card.mods` + `ModificationRegistry.get_data(mod_id)` | 复用 `_refresh_installed_list` |
| 模块核心属性 | `_build_stat_delta_preview(mod_data)` 或 `_format_effects_for_display` | 复用现有 |
| 安装要求/材料 | 现有 `_show_mod_details` 的成本计算逻辑 | 迁移到操作台 |

### D. 风险点与保护措施

1. **实例守卫**：`_resolve_instance_or_warn` + `_install_modification` 的 `instance_id.is_empty()` 拦截 —— **绝对保留**，防改造污染模板
2. **同步 free 子节点**：`_refresh_installed_list` 等用 `remove_child + free()`（非 queue_free）—— **保留**，防 CenterContainer 撑高
3. **InstallButton 重连**：disconnect 旧 callable 再 connect —— **保留**
4. **嵌入式模式**：`_apply_embedded_layout` 隐藏 TitleRow/LeftPanel/ResourceBar —— **保留并适配**（右栏单位面板和底部台不依赖左栏，嵌入式下正常工作）
5. **ResultLabel 永占位**：custom_min_y=22 不切 visible —— **保留**

### E. 验证

1. `godot --headless --check-only`（语法 + autoload 链路）
2. Grep 核对：删除的节点名在 gd 无残留引用；新增的 @onready 路径在 tscn 都存在
3. 静态核对：`_refresh_unit_panel` / `_refresh_action_deck` 数据链路完整（estimate_power_score → PowerTiers → get_modified_stats → mods）

## 实现方式
- tscn：直接编辑文本（结构变化大，增量 scene_* 工具太慢），保留可复用的 StyleBoxFlat
- gd：用 `script_patch`（replacements 精确替换关键函数 + 新增函数）
- 最后 `godot --check-only` 验证

## 默认决策（用户未明确时的判断）
- **完整重构**（非仅改右栏）—— 最贴合"按设计稿改"的诉求
- **保留嵌入式模式**—— 避免破坏背包→情报 Tab 路径
- **战力口径用 `estimate_power_score`**（养成口径，与现有 `_get_card_tier_str` 一致，非 `card.get_current_power()` 旧公式）
