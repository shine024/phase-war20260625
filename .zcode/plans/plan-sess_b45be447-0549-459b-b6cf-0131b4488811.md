# 修复：战斗中打开设置面板看不到（输入被吞但面板不可见）

## 根因（已确认）
设置面板的"关闭→重开"可见性链路不对称：

1. **关闭时**：`settings_panel.gd._on_close()`（L197-199）设**内层 PanelContainer** `visible = false`，emit closed → `_close_overlay` 只设 `settings_overlay.visible = false`，**内层 visible=false 状态被保留**
2. **重开时**：`_open_overlay`（L331）设 `overlay.visible = true` + `CenterContainer.visible = true`，但**不复位内层 PanelContainer 的 visible**（它仍是上次关闭时的 false）
3. 结果：全屏 Backdrop（mouse_filter=STOP）显示并吞掉所有点击，但真正的设置面板 invisible → "看不到 + 点不了其他按钮"

**对比 AFK 面板**（正确范式）：AFK 在 `_open_overlay` 有特判调 `ap._open()`（L369-374）复位内层可见性。settings 没有这样的特判。

## 修复方案（与 AFK 范式一致）
在 `_open_overlay` 的 panel_key 分支里加 settings 特判，打开时复位内层 PanelContainer 的 visible。

**改动文件**：`scenes/main.gd`（1 处，约 4 行）

在 `_open_overlay` 的 `elif panel_key == "afk":` 分支后（L374 之后），加：
```gdscript
elif panel_key == "settings":
    # settings_panel.gd._on_close() 会把内层 PanelContainer 设为 invisible，
    # _open_overlay 默认只复位 overlay + CenterContainer，漏了内层 → 重开时
    # 全屏 Backdrop 显示并吞输入，但面板不可见。此处显式复位内层可见性。
    var sp: Node = overlay.get_node_or_null("CenterContainer/SettingsPanel")
    if sp is Control:
        (sp as Control).visible = true
```

## 为什么不直接改 settings_panel.gd
`settings_panel.gd._on_close()` 设 `visible = false` 是它自己的关停逻辑（可能被其他路径调用）。最稳健的修复点是在"打开"这一侧复位，与 `_open_overlay` 现有的 backpack/growth/afk/map/info 特判范式完全一致——每个面板的打开都有定制刷新逻辑，settings 补上自己的即可。

## 不改的东西
- `settings_panel.gd._on_close()` 的 visible=false（它的关停逻辑，保留）
- `settings_panel_popup.gd` 包装器（被 prune 释放后不参与，懒加载用的是 settings_panel.tscn 直挂 PanelContainer）
- Backdrop 的 mouse_filter=STOP（模态遮挡是设计意图，面板能显示后正常工作）

## 验证
1. Godot headless --check-only（语法）
2. 实机：战斗中打开设置 → 关闭 → 再打开，面板应可见且可操作
