# 改造特殊机制扩展计划（第二批次）

## 总览

基于上批次建立的成熟范式（UnitStats加字段 + table双向回写 + registry match + handler触发逻辑），实现 4 类新机制 + 修复 4 个语义错配改造 + 新增 8 个改造。

**用户确认的决策：**
- IFAK/急救包 → 一次性复活（修复语义错配）
- 爆反/拦截 → 2-3个核心（修复 arm_03 + arm_04 + 新增 1 个）
- 亡语 → 死亡治疗队友（不做爆炸/spawn）
- fort/universal → 堡垒3 + 通用2

## 第一部分：濒死复活机制（修复 inf_18 + rec_10）

**核心：HP归零时复活到 15% max_hp，每场战斗仅触发1次**

| 文件 | 改动 |
|------|------|
| `resources/unit_stats.gd` | +`revive_on_death:bool`、`revive_hp_ratio:float`(默认0.15)、`has_revived:bool`(运行时标记) |
| `resources/unit_stats_table.gd` | base_dict + 写回加3字段 |
| `scripts/systems/modification_registry.gd` | match 加 `ifak_revive` 分支；保留旧 `ifak_heal` 映射不变（向后兼容） |
| `scripts/battle/module_effect_handler.gd` | 新增 `on_death(dying, killer) -> bool`（读 revive_on_death + has_revived，未触发过则复活+标记+return true） |
| `scenes/units/construct_unit.gd` | `_die()` 在 RuneSpecialHandler.on_death 之后加 `if ModuleEffectHandler.on_death(self, _killer_for_mod): return`；新增 `on_revived()` 重置状态 |
| `data/modification_modules/infantry_mods.gd` | inf_18_ifak 的 effects 改 `{ifak_revive = 0.15}` |
| `data/modification_modules/recon_mods.gd` | rec_10_medkit 同上 |

## 关键设计决策

1. **复活用独立 on_death 钩子而非 RuneSpecialHandler**——两套数据通路不混用
2. **拦截在 resolve_hit 之后、hp扣减之前 return**——绕过伤害符合"没被打到"语义
3. **反伤作用于实际扣血量(hp_loss)**——复用 on_damage_taken 现有签名
4. **亡语治疗与复活共享 on_death**——复活 return true 时亡语不触发（复活了就没死）
5. **堡垒区域机制复用 ModAuraHandler 光环广播**——不新建区域节点
6. **相位护盾用独立池而非复用 shield 字段**——避免与护盾卡/符文/法则冲突
7. **4个修复改造保留旧 effect key 在 registry**——向后兼容旧存档
