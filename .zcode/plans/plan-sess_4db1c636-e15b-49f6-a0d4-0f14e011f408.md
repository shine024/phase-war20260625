# 情报面板光环与特殊功能修复方案

## 问题诊断（已核实）

用户说"特殊功能战斗卡的光环没写出来""战斗中的光环加成"——核实后确认战斗卡（`CardResource`）本身**没有** special_traits/active_ability 字段（那是相位仪的），战斗卡的"特殊功能"实际由三套机制承担：**平台光环**（医疗/雷达/堡垒等，由 platform_type 派生）+ **改造光环**（ally_* 改造广播）+ **词条特殊机制**（已显示）。情报面板（card_info_panel.gd）存在 6 个显示缺陷：

| # | 问题 | 你选择修 |
|---|------|---------|
| 1 | **卡牌模式（背包/商店）看不到光环**——`_build_aura_text` 要战场 unit 节点，`show_card_info` 没有 | ✅ |
| 2 | **战场光环只显示名字不显示数值**——只输出"医疗光环"，不显示"治疗8%/3秒" | ✅（提供口径带数值） |
| 3 | **MEDIC 医疗光环查不到**——platform_type==9 自驱不注册 AuraManager，战场点开医疗车光环行空 | ✅（附带） |
| 4 | **敌方单位显式隐藏光环**——敌方构装单位的光环也注册到 AuraManager（影响敌方群体），却隐藏 | ✅ |
| 5 | **tags 标签从不显示**——card.tags（infantry/armored/fortress 等）情报面板零展示 | ✅ |
| 6 | **"提供"与"受到"口径混在一行**——平台光环显示"提供的"，改造光环显示"受到的"，混在一起 | ✅（提供+受到都显示，但分开标注） |

## 实现方案（全部集中在 card_info_panel.gd，不改战斗逻辑）

### 改动点 1：重构 `_build_aura_text(unit)` —— 分"提供 / 受到"两段 + 补数值

当前函数把"本单λ提供的平台光环"和"本单λ受到的改造光环"混在一行。重构为两段清晰口径：

```
【提供的光环】
  · 医疗光环：每3秒治疗全体友军8%最大生命（★N加成→X%）
  · 雷达侦测：全体友军暴击+10%
【受到的光环加成】
  · 改造光环（来自 X#1）：轻攻+10%, 暴击率+5%
  · 平台光环（来自 X#2）：受到堡垒减伤+6%
```

**提供段（来自 AuraManager + MEDIC 补丁）：**
- 平台光环：`AuraManager.get_unit_aura_types(unit)` 拿到类型列表，再调 `AuraData.get_aura_params(cat, star)`（star = `AuraManager.get_unit_star(unit)`）取数值，格式化成"治疗8%/3秒""暴击+10%"等。
- **MEDIC 补丁**：platform_type==9 不在 AuraManager，但 unit 有 `is_player` + `stats.platform_type==9` → 面板显示层直接补一条"医疗光环"，数值用 `AuraData.get_aura_params(MEDIC_HEAL, star)`（不动战斗逻辑）。
- 改造光环提供方：读 unit 自身 meta `mod_aura_summary`（这是它装了 ally_* 改造后给友军的 buff），格式化"轻攻+10%"等。

**受到段（遍历友军查谁在给它加 buff）：**
- 改造光环受到：已是当前逻辑（读 `mod_aura_applied` meta），保留并改为标注"来自 source"。
- 平台光环受到：遍历同阵营友军的 `AuraManager.get_unit_aura_types(ally)`，若单位有 RADAR/SCOUT/FORTRESS/COMMAND 等一次性光环（这类是注册即对全体生效），本单λ即"受到"。用 `get_aura_params` 算数值。MEDIC/CARRIER 是周期治疗，不属于"持续 buff"，不列在受到段（避免与实际治疗结算口径冲突）。

### 改动点 2：新增 `_build_aura_preview_text(card, stats)` —— 卡牌模式预览

`show_card_info(card)` 路径（背包/商店/相位仪）没有 unit 节点，无法查 AuraManager。新增纯数据预览函数：
- 入参：`card: CardResource` + 已构建的 `stats: UnitStats`（`_refresh_info_sections` 已构建缓存）
- 从 `stats.platform_type` 反推光环类型（复用 construct_unit.gd L223 的 match 表：3→堡垒, 4→雷达, 5/10→侦查, 8→维修, 9→医疗, 12→指挥）
- star 用 `card.enhance_level`（实例卡养成等级）或回退 1
- 调 `AuraData.get_aura_params` 取数值，格式化"部署后提供：医疗光环 治疗8%/3秒"
- 改造光环预览：读 `card.mods` 里的 ally_* 改造（复用 `_extract_aura_summary_to_meta` 的提取逻辑，或直接调 `unit_stats_table._apply_mod_stat_effects` 已写入 stats meta 的 `mod_aura_summary`），预览"装了某改造 → 会给友军轻攻+10%"
- 接入点：`_refresh_info_sections` L483 nurture_label 拼接处，追加 `_build_aura_preview_text(card, stats)`

### 改动点 3：敌方单位显示光环

`_show_enemy_construct_unit`（L1199）当前注释"敌方不显示光环"并强制隐藏 nurture section。改为：
- 调用一个精简版 `_build_enemy_aura_text(unit)`：只显示"提供的光环"段（敌方单位的 platform_type 同样驱动 AuraManager 注册，敌方群体吃 buff）。敌方"受到的光环"同理可遍历 enemy_units 查。
- 不隐藏 nurture section（让光环行能显示），但仍不显示强化/改造（敌方无养成）。

`_show_generic_enemy_unit` / `_show_enemy_phase_master_unit`：普通敌兵和相位师单位不提供光环（无 platform_type 注册逻辑），保持隐藏，不改。

### 改动点 4：tags 标签显示

在 `_refresh_info_sections` 的类型行（type_label）或新增一行，显示 `card.tags` 的中文翻译：
- 新增 `_format_tags_cn(tags) -> String`：infantry→步兵、vehicle→载具、armored→装甲、support→支援、aircraft→空中、fortress→堡垒、immobile→固定、boss→BOSS、elite→精英
- 接入点：type_label 末尾追加，如 `"虎式坦克 / 直射 · [装甲·载具]"`，或 nurture_label 顶部加一行"定位：装甲·载具"

## 不改的东西（向后兼容）

- **战斗逻辑零改动**——所有光环的实际生效（AuraManager/CardAbilityManager/ModAuraHandler）不动，只改显示层。
- **MEDIC 不强行注册 AuraManager**——显示层补一条，避免动战斗时序。
- **相位仪的 special_traits/active_ability**——那是相位仪字段，由 bottom_instrument_bar 等显示，情报面板不涉及（用户前提已纠正）。
- **词条特殊机制**（溅射/连锁/护盾等）——`_build_affix_summary_lines` 已显示，不重复。
