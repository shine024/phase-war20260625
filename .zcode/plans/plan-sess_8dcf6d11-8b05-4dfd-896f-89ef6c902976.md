# 自动部署修复：每卡槽最多 1 个 + FIFO 阻塞

## 问题

1. **alive limit 按 card_id 而非 instance_id 统计**：`_reach_alive_limit_for_card` 用裸 `card_id`（如 `cold_t72`）统计场上存活数，把 `cold_t72#1` 和 `cold_t72#2` 视为同一卡。用户期望"每个卡槽的卡在场上只能有 1 个"，即按 instance_id 统计。
2. **auto-deploy FIFO 阻塞**：`_deploy_next()` 始终尝试队列头（最左卡），失败时重试 20 次（8 秒）才跳过，阻塞后续卡。

## 修复方案

### 修改 1：`battle_spawn_system.gd` — alive limit 改按 instance_id 统计

**改动函数（4 个）：**

- `_has_alive_player_unit_from_card(card_id)` → 新增 `_has_alive_player_unit_from_instance_id(inst_id: String)`，读 `source_instance_id` meta
- `_count_alive_player_units_from_card(card_id)` → 新增 `_count_alive_player_units_from_instance_id(inst_id: String)`，读 `source_instance_id` meta
- `_reach_alive_limit_for_card(card_id)` → 重构为接受两个参数 `_reach_alive_limit_for_card(base_card_id, platform_card_id)`，按 platform_card_id 是否含 `#` 决定统计方式：
  - 有 `#`（实例卡）：用 `source_instance_id` meta 统计，`equipped_count` 恒为 1（每个实例自身），上限 = 1 × 幻影倍率
  - 无 `#`（裸卡 ID，旧兼容）：用原逻辑 `source_card_id` meta 统计
- `_is_phantom_clone_for_card(card_id)` → 改用同样新逻辑，按 instance_id 判断

**调用处（L480）：**
```gdscript
# 改前
if _reach_alive_limit_for_card(base_card_id):
# 改后
if _reach_alive_limit_for_card(base_card_id, platform_card_id):
```

**旧函数保留不动**（`source_card_id` meta 路径仍有其他调用方可能在用），新增 `source_instance_id` 统计函数。

### 修改 2：`auto_deploy_controller.gd` — FIFO 阻塞修复

**`_deploy_next()` 改为轮转尝试：**

不再只试 `_deploy_queue[0]`，改为从头遍历队列，找**第一个能部署成功的卡**：
- 遍历队列，对每张卡尝试部署
- 成功：pop 该卡，重置 fail_streak
- 失败（能量不足等临时原因）：标记 skip，继续尝试下一张
- 全部失败：fail_streak++，下次整轮重试
- fail_streak > FAIL_GIVEUP：pop 队列头（放弃最久的卡），避免永久阻塞

**`_on_unit_died` 补阵优化：**
- 不再只 `is_empty()` 时补阵——改为死亡后清空队列重新收集，确保补阵能感知当前战场状态（哪些实例已在场上）

## 影响范围

| 文件 | 改动量 | 风险 |
|------|--------|------|
| `battle_spawn_system.gd` | +2 函数 + 1 函数签名扩展 | 低（新增 fallback 路径，旧路径保留） |
| `auto_deploy_controller.gd` | `_deploy_next` 重写 ~30 行 | 低（行为更优：不再阻塞） |

**向后兼容**：裸 card_id 路径保留（旧存档无 instance_id 的卡仍按原逻辑），instance_id 路径覆盖新卡。手动部署同样受益（走同一个 `_reach_alive_limit_for_card`）。

**幻影克隆不受影响**：幻影乘率仍叠加在 instance 上限（默认 ×1），激活幻影能力时上限变 2（每个实例卡槽仍最多 2 个）。
